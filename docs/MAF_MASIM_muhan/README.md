# MASim × Microsoft Agent Framework 混合模拟基础设施

**Muhan**

本方案建设一个可组合主体、行为、环境和交互机制的模拟运行系统。核心使用图景是：**大量主体持续存在，多种局部活动按需发生；活动可以跨模拟时刻持续，同一主体可以参加多个未结束的活动。**

**MAF 承载复杂行为与局部协作，MASim 的适用资产按需迁移，系统统一管理模拟时间、环境后果、流程接续和执行资源。** 参考实现使用 Python、MAF、Ray、PostgreSQL 与 BlobStore。长期状态独立保存，由共享执行进程（worker）按就绪任务开展计算。

本文描述目标架构与实现计划。跨时刻活动、联合恢复与规模能力仍需通过集成测试和负载验证，验收要求见 [12 · 实施与验收](12-implementation-and-acceptance.md)。

## 3. 方案的核心判断

| 目标 | 采用的方法 | 需要验证的限制 |
|---|---|---|
| 主体规模与计算量分别增长 | 主体持久化、事件激活、有界共享 worker | 装载与序列化成本，密集激活下的调度开销 |
| 多种行为和环境能够组合 | 统一数据接口、可替换的计算机制、环境能力注册 | 新增组件是否仍需修改通用协调代码 |
| 复杂主体保留内部经验 | 持久内部角色、协调规则与会话隔离 | 内部授权、长期更新、嵌套与角色变化 |
| 独立行为和局部活动能够持续 | 统一记录流程进度，通过模拟反馈接续 MAF 工作流 | 当前观察、局部会话与待响应请求能否共同恢复 |
| 重叠活动有明确后果 | 固定版本读取、跨模块统一处置、联合提交 | 组合失败、资源重新分配、慢任务和提交热点 |
| 长运行能够恢复和检查 | 稳定任务身份、调用账目、提交记录、完整状态引用 | 重复执行、未知外部结果和故障窗口 |

系统允许主体在环境支持的范围内选择对象、参数、时机、沟通及合作方式。领域作者定义行动后果和约束；使用哪个行为机制、提供哪些信息、是否采用抽样或聚合，均属于可查看的模型配置。
