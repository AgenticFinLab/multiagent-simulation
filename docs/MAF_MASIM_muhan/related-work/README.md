## 2. 设计依据及适用范围

| 来源 | 相关机制 | 支持范围与限制 |
|---|---|---|
| MASim 通用实现 | 主体初始化、四阶段执行、通信与记录 | 提供可迁移资产，适配后需重新验收 |
| MAF 参考源码 | 请求、响应、会话、嵌套流程与 checkpoint | 提供适配入口，当前观察、角色状态与联合恢复需额外检查 |
| MAF 官方文档 | 请求响应、checkpoint、会话、Group Chat、中间件 | 描述原生构件，具体接口需与依赖版本对应 |
| OASIS / AgentSociety | 行动、环境、信息分发与规模化执行 | 规模与实验结果属于作者报告，不直接对应本系统能力 |
| Generative Agents | 记忆、检索、反思与规划 | 提供行为组件参考，实际效果取决于模型设置 |
| 社会模拟立场论文 | 环境参与的模拟器形式化定义 | 支持职责拆分，不证明工程选型最优 |
| Mesa / Matrix / LangGraph / TradingAgents | 模型组件、分布式执行、状态管理与角色协作 | 提供机制参考，组合后的运行性质仍需验证 |
| Ray / PostgreSQL | 异步 Actor 与事务 | 提供执行和持久化构件，应用协议仍需实现验证 |

## 3. 怎样使用这些证据

**已有事实**描述来源明确给出的接口、机制或作者报告。**设计推论**说明这些机制在本方案中的用途。**待验证项**列出新组合需要获得的证据。

规模数字需同时关联活跃率、交互量、硬件、行为复杂度和运行时长。其他框架的容量或吞吐不能直接作为本系统的验收结果。

缓存、聚合、混合行为和异步执行的收益取决于负载与实现条件；它们对信息、行为分布和时间语义的影响需要分别检验。

这些依据用于解释设计选择。系统能力按[实施与验收](../12-implementation-and-acceptance.md)形成独立证据。
