# 设计决策与待确认项

[返回总览](README.md) · [实施与验收](12-implementation-and-acceptance.md)

本页汇总设计目标、技术选择、待确定的实施条件及需要原型验证的问题。

## 1. 设计目标

| 编号 | 方向 |
|---|---|
| G1 | 先建设兼顾规模、灵活性与运行有效性的模拟基础设施，领域实验随后推进 |
| G2 | 大量主体持续存在，多种局部活动按需发生 |
| G3 | 活动可以跨模拟时刻持续，同一主体可以参加多个未结束活动 |
| G4 | 充分利用 MAF 的行为、工作流和运行支撑能力 |
| G5 | MASim 按需要迁移和发展适用资产，不要求保留完整旧框架 |
| G6 | 主体能够形成不同提议和行动路径，模型可以使用声明假设与合成配置 |
| G7 | 以完整运行链路验证基础设施能力，原型逐步扩展到终态 |

## 2. 本稿采用的技术路线

| 编号 | 选择 | 依据与代价 | 主文档 |
|---|---|---|---|
| D1 | 持久主体状态与共享 worker 分离 | 分别管理主体容量与计算量；增加装载和序列化 | [08](08-execution-and-scaling.md) |
| D2 | MAF 负责复杂行为和局部流程；函数直接接入 | 复用运行构件，轻行为保持低开销；需统一合同 | [04](04-agents-and-memory.md) |
| D3 | 持续活动 + WorkflowBridge + 已提交 checkpoint | 支持跨时刻、重叠与等待；跨实例完整接续需验证 | [06](06-activities-and-workflows.md) |
| D4 | 离散事件、有序阶段、保守屏障 | 观察和后果清楚；慢任务限制阶段推进 | [07](07-time-and-communication.md) |
| D5 | 环境统一解释行动后果，主体和活动按规则更新 | 明确资源与字段归属；共享环境可能成为热点 | [05](05-environment-and-actions.md) |
| D6 | Python + Ray + PostgreSQL + BlobStore | 复用执行经验并验证联合提交；增加部署成本 | [08](08-execution-and-scaling.md)、[09](09-state-and-recovery.md) |
| D7 | 每 run 一个逻辑提交所有者，任务与尝试分别记录 | 限制重复效果与旧实例写入；单 run 提交上限需测量 | [09](09-state-and-recovery.md) |
| D8 | 端点级总配额与独立调用账目 | 约束全局使用量；未知结果需要核对 | [08](08-execution-and-scaling.md) |
| D9 | 记忆、工具、聚合和混合行为显式配置 | 保留模型灵活性；不能把所有节流都视为语义不变 | [04](04-agents-and-memory.md)、[08](08-execution-and-scaling.md) |
| D10 | 先完整保留恢复依据，诊断允许采样 | 支持恢复与过程核对；持久 I/O 成本需报告 | [10](10-operation-and-observability.md) |

各项选择共同构成参考架构，其关键前提及验证方式见第 4 节。

## 3. 待确定的实施条件

| 问题 | 本稿建议 | 决定的内容 |
|---|---|---|
| 首轮验收重点是什么？ | 同时覆盖稀疏持续主体、重叠活动、高争用环境三类工程负载 | 原型优先级和资源分配 |
| 当前是否接受每 run 保守推进的时间路线？ | 先建立完整语义与受控一致性证据，再依据瓶颈评估分区推进 | 是否按 D4 / D7 进入实现 |
| 首版外部能力到什么深度？ | 完成 MAF、只读/计算工具、模拟效果与协议扩展合同；完整 A2A、复杂界面和外部写操作随后安排 | 避免首版同时承担平台化工作 |

实施前需确定计算资源、模型端点及调用预算；数值目标结合工程负载制定。

## 4. 需要原型回答的技术问题

| 风险 | 需要的证据 | 验证失败后的边界 |
|---|---|---|
| MAF 跨实例状态不完整 | 多请求、成员会话和固定 executor 的接续探针 | 修正适配层，不能用空会话继续 |
| 动态成员难以保持图与请求一致 | 加入、退出、迟到响应和取消测试 | 固定调度节点与序列化协议需调整 |
| 阶段屏障限制吞吐 | 分解慢调用、排队与空闲时间 | 不通过擅自降级行为掩盖瓶颈 |
| 单次提交或环境热点过重 | 高争用负载的后果处理与事务指标 | 先优化对应路径，再评估需要新时间机制 |
| 配额与未知调用恢复不清楚 | 丢失响应、服务重建、重复尝试测试 | 保留 unknown 状态并暂停核对 |
| 状态与 checkpoint 体积失控 | 长活动、长记忆及恢复保留期测量 | 调整保留和装载方式，信息压缩另记模型变化 |
