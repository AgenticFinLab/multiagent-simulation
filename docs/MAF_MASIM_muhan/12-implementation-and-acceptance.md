# 12 · 实施计划与验收

[返回总览](README.md) · 前一篇：[迁移与工程](11-migration-and-engineering.md) · [决策与待确认项](decisions.md)

本篇规定实现顺序。最终能力由 [01](01-scope-and-requirements.md) 定义，架构与合同由 02–10 定义。早期缩小用例和负载，终态保留持续主体、复合角色、跨时刻活动、重叠参与、分布式执行及恢复。

以下里程碑均为待实施和验收的目标，完成情况以集成测试和负载报告为依据。

## 1. 里程碑

| 阶段 | 交付 | 通过条件 | 未通过时的处理 |
|---|---|---|---|
| M0 · 实施合同与资源确认 | 明确状态归属、输入、处置、模型绑定和首轮负载 | 状态归属清楚，执行、反馈与恢复流程完整；依赖、资源及实施范围明确 | 修订所属合同与未决条件 |
| M1 · 骨架与关键机制验证 | 新仓库；独立/活动接续、嵌套角色、当前视图与部分反馈探针；事务和 Blob 链路 | 跨进程恢复原请求、会话与来源；重复反馈不重复执行；候选和生效引用分开 | 修正适配与持久合同，暂不扩大负载 |
| M2 · 基本运行链 | 群体初始化、原子与固定角色复合主体、行为及机制任务、联合处置、提交与记录 | 独立行为能够等待并恢复；主体行动可追溯到输入与决策；组合失败释放候选资源；准备与判断的输入输出明确 | 修正跨模块合同或依赖 |
| M3 · 持续与重叠活动 | 动态成员、受控角色变化、有界嵌套、模拟等待、跨活动长期更新 | X / Y 覆盖成功、拒绝、取消、退出和迟到；长期状态持续保留、各活动会话隔离；等待释放 worker | 修正生命周期、信息或后果规则 |
| M4 · 共享执行与故障恢复 | Ray 池、端点总配额、所有权、阶段依赖恢复与模型核对 | 乱序与多 worker 满足受控一致性；预算不足时暂停，恢复复用原上游结果；故障矩阵通过 | 在失败层修正并保留小型输入 |
| M5 · 工程交付与负载报告 | 文档、扩展示例、检查器、负载与限制报告 | 干净环境可复现工程用例；R1–R8 有证据；容量和成本可解释 | 按未通过的需求补足实现与验收证据 |

推进顺序从关键机制验证转入完整运行，再增加动态行为与负载。M1 使用小型合成组件确认接续和持久化；M2 以固定角色完成端到端流程；M3 加入动态成员、角色变化和重叠参与；M4 检查分布式执行与故障恢复，M5 汇总交付。每阶段按既定通过条件结束，新增需求另行安排。

## 2. 需求与验收对应

| 需求 | 关键验收 | 最晚形成证据 |
|---|---|---|
| R1 持续主体与群体 | 稳定生成原子/复合主体，跨活动保留，停用清理与稀疏激活 | M2 / M5 |
| R2 主体结构与异质行为 | 规则、LLM、混合共用合同；角色长期状态、汇总、嵌套与授权 | M3 |
| R3 环境与行动 | 新操作、灵活参数、跨模块联合处置和失败反馈 | M2 / M3 |
| R4 持续活动 | 独立与活动实例跨时刻接续，动态成员 | M3 |
| R5 重叠与时间 | 同主体双活动、角色会话隔离、资源竞争与等待环 | M3 / M4 |
| R6 执行与成本 | 行为及机制任务有界派发、端点总配额、绑定及规模分解 | M4 / M5 |
| R7 一致恢复 | 长期状态、接续位置、部分响应、阶段依赖和配置核对共同恢复 | M4 |
| R8 操作与检查 | 查询、暂停、来源定位、回放、导出及独立检查 | M5 |

## 3. 验收用例

### 3.1 主体、记忆与活动

| 用例 | 构造与断言 |
|---|---|
| 复合主体的对外身份 | 两个子角色提出不同建议，管理者汇总；对外请求归于父主体，来源可定位，未授权角色请求被拒绝 |
| 两层状态 | X 结束后角色长期记忆保留，新流程获得允许内容；局部会话按实例隔离，不成为第二份长期状态 |
| 重叠角色会话 | A 的同一角色参加 X、Y，分别植入私有标记；检查实际提示、工具读取和下阶段长期更新 |
| 嵌套与汇总 | 有界两层角色树包含函数及受控模型响应；检查身份、表决/否决结果、失败分支和调用归因 |
| 角色与成员变化 | 等待边界退出或停用、再创建同名角色；恢复原绑定后应用控制变更，旧答复不交给新身份，清理和其他路径继续 |

### 3.2 时间与流程接续

| 用例 | 构造与断言 |
|---|---|
| 无活动的等待 | A 独立申请资源后保存 checkpoint；新进程接收反馈，继续原 behavior_instance_id，无须 activity_id |
| 新观察接续 | checkpoint 保存旧资源值；下一阶段改变资源并提供部分反馈；模型和查询工具均读到当前授权值，旧值仅作历史 |
| 多请求与重复反馈 | 新进程分批提供响应，保留未满足等待；恢复重发不重复申请，相同响应去重、冲突响应报错 |
| 待请求期间周期触发 | 原实例 waiting 时多次触发周期事件；按定义合并/推迟，不创建覆盖其会话的新实例 |
| 消息与期限 | 延迟消息到期才可见，模拟期限与 API timeout 分别处理，重复投递只消费一次 |

### 3.3 联合处置与机制计算

| 用例 | 构造与断言 |
|---|---|
| 组合失败后的再分配 | A 的加入+预约组因资格失败，B 竞争同一资源；A 无部分成功，B 按声明规则获得分配机会 |
| 组合成功与清理 | 加入+预约一同成功；取消时成员、资源、待请求和通知一致处理，失败反馈不被写成成功状态 |
| 同主体字段与资源竞争 | X、Y 同阶段修改共享字段并申请同一份资源；按父主体及环境规则处置，不受返回顺序影响 |
| 记忆与环境机制任务 | prepare 摘要进入指定角色输入，adjudicate 消费已保存提议；resolve 与提交重试不触发模型调用 |

### 3.4 恢复、一致性与扩展

| 用例 | 构造与断言 |
|---|---|
| 阶段依赖恢复 | 摘要结果封存后、环境判断前中断；恢复使用原输入和上游输出，缺失封存载荷时暂停 |
| 模型与部署绑定 | 相同模型绑定下调整 worker/连接可恢复；同名端点换模型或解码被识别，未知 revision 状态明确 |
| 不完整结果 | 一条并发分支先输出，另一条失败；不提交部分片段或提前结束活动 |
| 故障与旧实例 | 提交前后中断，旧 worker 或协调进程返回；只有有效尝试和 owner_epoch 生效 |
| 预算中途耗尽 | 部分行为或机制任务完成后暂停；补预算后复用候选，不更换模型或重新抽样已选中结果 |
| 状态重建 | 从初态与提交记录重建主体、角色、环境、活动和实例，与在线状态一致 |
| 执行布局变化 | 固定响应和随机流，改变 worker、批量及返回顺序，比较状态、处置与逻辑事件 |
| 组件扩展 | 增加行为、环境能力或机制任务及活动模板，通用协调循环无需改写 |

验收同时检查实际输入、结果、持久记录和下一次行为。使用小型已知结果或独立状态检查器核对资源总量、身份权限和消费次数，确保结论有独立于被测组件输出的依据。

MAF 接续验收使用固定版本的真实框架、嵌套流程和 Agent 会话，模型响应可以受控；检查重点是状态、信息与后果是否符合上述规则。

## 4. 三类工程负载

数值是待 M0 结合资源确认的测量输入，尚不是已达到的规模或真实模型预算。

| 负载 | 起始与扩展配置 | 重点测量 |
|---|---|---|
| 持续主体与稀疏激活 | N = 100、1,000、10,000；1% / 10% 活跃率 | 状态容量、热内存、激活定位、装载和派发 |
| 局部复杂协作 | 100 个主体；10–100 项活动，每项 2–5 个主体；部分主体含 2–3 个内部角色 | 角色与实例数、checkpoint 体积、等待、会话隔离和恢复延迟 |
| 共享环境高争用 | 100–1,000 个活跃主体竞争资源，加入组合失败、延迟、重复和中断 | 联合处置、事务吞吐、尾延迟和恢复 |

为各类负载提供函数行为与受控响应版本，使用真实 MAF 测量框架运行开销。prepare、behavior、adjudicate 的耗时与调用分别报告。真实端点探针另列模型、调用量、配置和预算。

受控响应吞吐不能推断真实模型吞吐；注册主体数不能代替复杂活动并发。硬件和验收阈值在实施前确定，不依据当前文档推断容量。

## 5. 验收证据

- 源码提交、依赖锁、模型与执行配置、模型核对状态及初态摘要。
- 硬件、worker、角色及实例数量、状态与消息大小、响应分布、故障位置。
- 实际断言、原始输入输出、处置、提交、调用与接续关联。
- 通过项、未覆盖项、失败输入和已知限制。
- 容量、吞吐、成本、延迟分解和恢复结果，分别呈现。

验证范围随核心合同、依赖和失败路径的变化更新，并保留受影响用例的运行结果。

## 6. 完成条件与范围控制

交付要求 R1–R8 均有证据，工程示例可由其他开发者独立运行，组件有公开合同和扩展示例，恢复与规模限制可解释。

关键性质失败时停止对应扩量或交付判断，保留可复现的小型失败用例；其他独立工作可以继续。

领域环境扩展、真实事件研究、EPG 领域转换、多租户平台和新的高性能时间算法后续单独规划。
