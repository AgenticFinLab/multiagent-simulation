# 07 · 模拟时间、调度与通信

[返回总览](README.md) · 前一篇：[活动与 MAF](06-activities-and-workflows.md) · 下一篇：[执行与规模](08-execution-and-scaling.md)

## 1. 时间路线

采用离散事件与保守阶段推进。模拟坐标为 `(t, p)`：t 是模型声明的模拟时间，p 是同一时刻内有序的反馈阶段。

| 规则 | 含义 |
|---|---|
| 阶段内固定读取 | 全部任务引用同一已提交 state_version |
| 完整阶段生效 | 必需任务到齐后，形成一次联合处置与提交 |
| 即时后果后续可见 | 本阶段产生的即时反馈最早在 (t, p+1) 消费 |
| 延迟后果未来可见 | 延迟 d > 0 时安排到未来 t，阶段由事件规则确定 |
| 顺序与物理执行分离 | 模型优先级、逻辑身份及依赖决定处理顺序 |
| 没有隐式时间跳跃 | 无新事件时按等待或完成条件处置 |

MAF superstep、模型调用耗时和模拟坐标分别记录。内部计算增加运行成本；只有模型声明相应耗时，才增加模拟时长。

## 2. 一个模拟阶段内的工作顺序

到期事件包含 event_id、kind、target、coord、source_id、payload_ref。调度先固定读版本、到期事件和阶段规则，再按下列依赖执行。

| 工作阶段（work_stage） | 执行内容 | 可以读取 | 输出的去向 |
|---|---|---|---|
| 输入准备（prepare） | 可选的摘要、反思、模型重排等机制任务 | 固定状态、已到达消息、授权记忆 | 指定主体或角色的派生输入 |
| 行为计算（behavior） | 独立行为、活动接续、复合主体内部流程 | 当前 ActorView、合法局部会话、授权的 prepare 结果 | 请求、候选主体更新与接续状态 |
| 后果辅助计算（adjudicate） | 可选的环境辅助判断 | 声明的环境投影、已保存请求及机制结果 | 联合处置的校验输入 |
| 处置与提交 | 联合处置与各模块的更新计划 | 完整候选、固定状态、定时事件与固定随机流 | 一次提交及后续模拟事件 |

前三项计算均发生在**同一个模拟坐标 (t, p)** 内，未配置的机制任务可以跳过。主体提出行动后，在后续 p 阶段收到环境反馈。

PhasePlan 保存各工作阶段的生成规则。后续任务可依赖已选中的上游结果，例如根据行为请求生成环境判断任务。每批任务派发前，将其身份、依赖和输入引用固定并持久保存，称为封存。后续执行及恢复均以这份记录为准，worker 返回次序不改变已封存的输入或任务集合。

各工作阶段的任务依赖需有界、无环，调度器按可运行集合和并发限额派发；模型调用全部来自已登记任务。需要读取本阶段最终后果的机制，安排到下一个模拟阶段。

纯检索与权限投影是固定版本的只读计算，不经 ModelAccess；涉及模型的计算统一进入执行池。prepare 结果只向授权消费者提供，不构成其他主体可见的提前状态写入。

## 3. 事件、触发和屏障

每个模拟阶段执行：

1. 选择最早到期事件，固定 phase_id、读版本及输入依据。
2. BehaviorManager 合并同一行为实例的到期输入；waiting 实例只使用声明的接续通道，其他触发按规则推迟。
3. 保存并执行各工作阶段的任务，封存用于后续依赖的候选。
4. ResolutionCoordinator 形成唯一处置，各模块生成状态与投递计划。
5. 原子提交后推进；失败或预算不足时保留阶段输入、候选与依赖以便恢复。

到期消息在当前可见坐标进入输入，其消费随阶段提交。环境定时事件在后果处理中改变状态；需要该变化的主体反应安排到后续阶段。

例如“t=5 的释放先于主体行动”，应将释放安排在 (5,0)，相应激活安排在后续 p。若二者同阶段，主体读取释放前状态，申请能否使用释放额度由显式分配规则决定。

保守屏障使观察与生效关系清楚。等待未来模拟反馈时可以释放 worker；本阶段的必需计算全部完成后才能提交，因此慢调用会增加阶段等待时间。

## 4. 消息的逻辑语义

| 字段 | 作用 |
|---|---|
| message_id、correlation_id | 消息身份及邀请、申请或问答关联 |
| sender、recipient、activity_id? | 对外模拟身份与活动范围 |
| behavior_instance_id、source_role_path? | 来源接续实例及内部提出角色 |
| sent_at、visible_at | 发送与允许接收的模拟坐标 |
| content_ref、schema_version | 不可变内容与类型 |
| delivery_policy | 投递、模型化丢失、期限与成员资格规则 |

复合主体对外使用父主体身份。发给其内部哪个角色由接收方的授权分派规则决定；subagent_id 不自动成为外界可直接访问的通信身份。

同一内容发给多人可共享载荷，每名接收者仍有独立 delivery_id。物理重投按身份去重；模型需要丢包或重复通信时，由通信组件生成显式模拟结果。

默认发送提交时解析并保存接收集合，到达时检查主体状态及模板的成员资格要求。订阅变化不改写历史接收集合。兴趣路由和邻接索引只加速已声明规则；代表者代收或消息摘要属于模型变化。

## 5. 等待、超时与外部输入

| 情况 | 处理 |
|---|---|
| 等待未来消息或时刻 | 提交行为实例的等待索引和接续位置，派发其他就绪工作 |
| 同坐标多个匹配响应 | 稳定排序，模板声明 any / all 规则 |
| 模拟期限到达 | 生成模型定义的超时响应或后果 |
| API 超时或配额不足 | 运行层有限重试或暂停，默认不改变模拟决策 |
| 没有事件但仍有等待 | quiescent，报告等待关系及可注入输入 |
| 即时反馈无限循环 | 达到 p 上限后暂停，保留因果链 |

默认同坐标有效答复先满足等待，再处理期限事件；其他规则由 TimePolicy 声明。等待结束、成员退出或角色停用后，迟到响应保留处置，不重新唤醒旧路径。

外部人工输入和远端结果显式指定注入坐标并保存内容。若采用墙钟期限决定模拟结果，须把它写入模型定义；事后排序不能消除这种依赖。

等待环是诊断线索。有未来事件或外部输入时未必构成死锁，系统报告未满足条件，不擅自取消活动。

## 6. 随机性与受控回放

初始化、行为、环境和通信使用独立逻辑随机流，从 run_seed、组件版本、角色及逻辑任务或事件身份派生，重试复用同一流。

并发任务不共享可变全局随机数发生器。真实模型重调用可能产生不同响应；记录回放使用已保存响应，恢复复用已封存候选，均不承诺重新调用模型后逐字相同。

对确定性组件或固定响应，改变 worker、批量和完成顺序，应保持已提交状态与逻辑事件关系。模型显式依赖墙钟或执行布局时，按其声明另行界定。

## 7. 贯穿示例：A 同时参加 X、Y

| 坐标示意 | X：A、B、C | Y：A、D | 系统处理 |
|---|---|---|---|
| t=0 | A 的内部角色共同形成提议，等待 B、C | 尚未开始 | 发送提议，保存 X 的局部会话和等待状态 |
| t=1 | B、C 答复到达，继续协商 | A 接受 D 邀请 | 两项活动使用 A 的已提交状态，分别维护局部会话 |
| t=2，同阶段 | X 申请 A 的资源 | Y 也申请该资源 | 同版本读取；必要判断任务完成后联合分配 |
| t=2，后续阶段 | 收到接受或拒绝反馈 | 收到相应反馈并继续 | 各自恢复 checkpoint，注入当前角色视图 |
| t=3 | 修改方案、结束或等待 | 完成或取消 | 保存允许的长期更新，主体状态跨活动保留 |

表中省略部分 p。固定响应分别构造 X 成功、Y 成功、撤回和延迟等分支，并检查角色状态、会话隔离、资源与恢复。行为机制决定实际路径。
