# 05 · 环境、行动空间与后果

[返回总览](README.md) · 前一篇：[主体与记忆](04-agents-and-memory.md) · 下一篇：[活动与 MAF](06-activities-and-workflows.md)

## 1. 可组合环境

环境定义资源、空间、关系、公共信息及变化规则。每个模块管理明确状态，公开可查询的投影和可申请的操作。

| 模块示例 | 管理内容 | 能力 |
|---|---|---|
| 资源 | 数量、所有权、占用区间 | 查询、申请、转移、释放 |
| 关系 | 成员、权限、订阅和连接 | 邀请、加入、退出、更新 |
| 空间 | 位置、区域及通达约束 | 移动、定位、局部观察 |
| 任务 | 工作、依赖、期限和完成状态 | 认领、协作、交付、撤销 |

环境可由声明假设和合成配置初始化。模块注册状态范围；跨模块组合同时涉及环境、活动或主体时，由 ResolutionCoordinator 组织统一处置，再生成各自更新。

## 2. 能力合同与行动空间

| 注册项 | 说明 |
|---|---|
| operation / version | 稳定名称、版本和参数 schema |
| actor eligibility | 谁可以提出操作，允许操作哪些对象 |
| observation | 主体可了解的能力、条件和结果范围 |
| validation | 参数、前提、资源和权限检查 |
| resolution | 同阶段冲突、优先级、随机流、组合处理器 |
| effects / feedback | 状态变化、定时事件、反馈及可见时间 |

主体在能力范围内自主选择对象、参数、顺序或放弃行动。例如 `resource.reserve(resource_id, amount, until)` 允许不同数量、期限和对象的申请，也允许失败后重新提议或转向合作。隐藏条件由环境检查，反馈按信息规则披露。

权限检查以请求所属的主体身份为准。内部角色代为发起请求时，还需核对它获得的授权。新增动作需注册相应后果，单纯输出自然语言或参数不会扩展操作集合。

## 3. 从提议到生效

```text
行为提出请求
  → 适配器绑定身份、检查结构
  → 收齐本阶段行为及声明的辅助计算
  → 跨模块联合处置，确定接受 / 拒绝 / 无效果
  → 各模块据同一处置生成更新与反馈计划
  → 一次提交后，在允许坐标提供结果
```

自然语言解释可作为行为定义中的一个步骤，输出结构化请求。环境需要 LLM 辅助判断时，将计算安排在后果辅助阶段（adjudicate）：读取指定版本的环境信息和已保存请求，返回 MechanismResult。结果经结构与范围校验后参与处置，状态修改仍由环境规则决定。

环境判断可使用模型声明的授权信息，并记录访问范围；反馈给主体时再按其权限筛选。所有模型计算共用执行池和 ModelAccess。联合处置、更新计划与数据库重试只使用已保存结果和固定随机流，不执行新的模型调用。

## 4. 联合处置与资源分配

以“加入活动并预约资源”为例，两项操作需要共同成功。若 A 申请加入 X 并预约唯一资源 R，B 同阶段也申请 R，而 A 不满足 X 的参与条件，则 A 的整组请求被拒绝，不产生成员资格、资源占用或成功记忆。R 随后仍可按规则分配给 B。

ResolutionCoordinator 负责协调这类跨模块决定，领域模块定义资格、冲突和后果规则。一次阶段处置采用以下顺序：

1. **规范化操作组。** 普通请求视为单项组；atomic_group_id 表示共同成功或失败的组，depends_on 表示显式前提。注册的组合处理器说明涉及的模块、条件与后果。
2. **汇集约束。** 各模块只读检查身份、资格、容量、期限和领域前提，主体更新规则同时检查 update_id 对应的字段修改与冲突，返回约束；此时不写入生效状态。
3. **有序评估。** 依赖按有向无环关系处理。同层按模型优先级、固定随机流及稳定身份决定顺序，不能使用 worker 返回次序。需要相互依赖的一组操作必须有注册的整体处理器，避免无界反复求解。
4. **暂配与整体决定。** 在候选分配中检查整个操作组。全部条件满足才接受并保留分配；失败则撤销该组暂配，再让后续合法申请竞争剩余资源。声明全局优化算法的模块也须返回完整且可核对的联合结果。
5. **固定处置。** 保存每个请求和组的 outcome、原因、资源分配、条件更新、反馈与来源，形成 DispositionPlan。
6. **生成计划并提交。** 环境、活动、主体、行为实例和消息模块使用同一份处置生成计划。CommitManager 核对跨计划约束，再提交状态与事件。

默认请求基于阶段初态。依赖同批操作的成功或允许使用本批释放资源时，必须写入组合与分配规则；所有权、额度和成员资格不会因某模块先执行而提前改变。

| 情况 | 处理 |
|---|---|
| 多项请求必须共同成功 | 同一操作组整体处置，各模块引用同一结果 |
| 申请竞争相同资源 | 由声明的分配策略处理，失败组不继续占用候选额度 |
| 更新依赖请求成功 | apply_if 引用已固定处置，满足后才生成相应更新 |
| 多个角色更新父主体字段 | 按父主体字段合并或冲突规则处理 |
| 取消活动、退出或停用角色 | 联合处理成员、权限、待请求、资源释放及通知 |
| 普通非法参数、无资格、无资源或行为提出不支持的组合 | 拒绝相应请求并返回允许披露的反馈，其他请求可继续 |
| 模型声明的组合缺少处理器、缺少冲突规则或更新计划矛盾 | 配置或运行错误，暂停提交并保留候选 |

主体内部汇总产生行动提议，资源分配由环境决定。依赖行动结果的记忆与属性更新以实际处置为准。例如，被拒绝的申请可记录为失败经历，不能据此增加资源余额；余额由所属环境模块维护。

数据库事务完整写入已确定的计划。独立合法行动可在同批提交，故障恢复则使用原输入重建相同处置。

## 5. 工具与环境连接

| 工具类别 | 运行方式 | 边界 |
|---|---|---|
| 只读模拟查询 | 读取当前身份视图或固定版本授权投影 | 不读取更新中的实时状态 |
| 纯计算 | worker 内计算 | 保存必要输入输出、版本与计算限额 |
| 产生模拟效果 | 返回 SimulationRequest，提交后提供反馈 | 返回请求不表示世界已经改变 |
| 外部检索 / MCP | 适配器读取模型允许的资料 | 来源、范围、返回内容与实际时间有记录 |
| 外部副作用 | 提交后由持久效果任务执行 | 幂等键、查询、失败和补偿规则明确 |

远端模型访问和主体获取新资料分别配置。模型调用不会自动授予网页搜索、文件系统或外部数据库权限。

首版使用只读查询、纯计算和模拟效果工具。外部资料由应用显式启用；真实外部写操作需通过效果适配器的恢复验收，不能假定它与数据库属于同一事务。外部协议入口见 [10](10-operation-and-observability.md#extensions)。

## 6. 环境扩展验收

新增模块交付状态 schema、操作定义、可见投影、分配与组合规则和小型示例。验证合法与非法参数、权限不足、重复请求、到期事件、整体失败后的资源再分配，以及恢复后的处置一致。

这些检查证明组件按声明规则运行。领域合理性由应用研究另行建立证据。
