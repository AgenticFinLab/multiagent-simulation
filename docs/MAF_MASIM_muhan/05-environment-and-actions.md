# 05 · 环境、行动空间与后果

[返回总览](README.md) · 前一篇：[主体与记忆](04-agents-and-memory.md) · 下一篇：[活动与 MAF](06-activities-and-workflows.md)

## 1. 环境是可组合的模型组件

环境定义模拟中的资源、空间、关系、公共信息及变化规则。每个模块管理一组明确状态，公开可查询的投影和可申请的操作。

| 模块示例 | 管理内容 | 可提供的能力 |
|---|---|---|
| 资源模块 | 数量、所有权、占用区间 | 查询、申请、转移、释放 |
| 关系模块 | 成员、权限、订阅和连接 | 邀请、加入、退出、更新关系 |
| 空间模块 | 位置、区域及通达约束 | 移动、定位、局部观察 |
| 任务模块 | 工作、依赖、期限和完成状态 | 认领、协作、交付、撤销 |

这些是组件示例，首版工程用例只需实现其中少量操作。环境可以来自声明假设与合成初始化，通用运行合同不要求领域历史资料。

模块在装配时注册状态范围。跨模块操作通过组合处理器生成一份 EffectPlan，防止各模块自行修改状态后才发现部分操作失败。

## 2. 能力合同与行动空间

每项能力注册以下内容：

| 项目 | 说明 |
|---|---|
| operation / version | 稳定名称、版本和参数 schema |
| actor eligibility | 谁可以提出该操作，允许操作哪些对象 |
| observation | 主体可了解的能力、条件和结果范围 |
| validation | 参数、前提、资源和权限检查 |
| resolution | 同阶段冲突、优先顺序、随机分配及组合规则 |
| effects / feedback | 状态变化、定时事件、反馈和可见时间 |

主体可以在该能力范围内自主选择方案。能力描述可以给出参数区间、可选对象和失败条件；不需要为每个状态预先指定唯一正确行动。隐藏条件由环境检查，反馈按信息规则披露。

例如 `resource.reserve(resource_id, amount, until)` 允许不同数量、期限和对象的申请，也允许放弃、重新提议或转向合作。新增领域动作需要定义其后果处理，任意文本不会自动变成有意义的世界变化。

## 3. 行动如何处理

```text
主体生成请求
  → 运行适配器绑定身份并校验结构
  → 环境检查权限、条件及同阶段竞争
  → 形成接受 / 拒绝 / 无效果处置
  → 与主体、活动及消息更新一起提交
  → 在允许的模拟坐标返回反馈
```

自然语言提议可以先由声明的解释组件转成结构化请求。解释发生在执行层，保存输入输出并计入模型调用预算；环境后果处理只消费已形成的请求及固定随机流。

采用确定性的后果处理接口。需要随机环境时，显式传入由事件身份派生的随机流；需要 LLM 辅助判断时，将判断安排为可记录的执行任务，结果再进入后果处理。数据库重试不能再次隐式调用模型。

## 4. 资源竞争与联合变化

| 情况 | 处理规则 |
|---|---|
| 同一资源被多个活动申请 | 收集同阶段申请后，由资源模块执行模型声明的分配规则 |
| 更新可以交换顺序 | 按字段规则合并，并保存各项来源 |
| 多项请求必须一起成功 | 请求显式声明原子操作组，由组合处理器整体接受或拒绝 |
| 主体更新依赖行动成功 | 更新携带相应 request_id 与条件，按实际处置决定是否应用 |
| 没有定义冲突规则 | 报告模型错误，保留候选和诊断 |

数据库的一次事务保证整批后果完整落地；各项行动的接受与拒绝由模型规则决定。一个行动被拒绝时，其他合法行动仍可在同批提交。

跨环境与活动的组合操作，例如“加入合作并预约资源”，先校验整体前提，再向环境和活动计划写入一致处置。普通请求默认基于阶段初态；若允许依赖同批另一操作的成功，需要显式声明并由组合处理器支持。各计划结果相互矛盾时拒绝提交，不能留下成功预约却未加入活动的半份组合结果。

主体长期记忆可以追加“申请被拒绝”，却不能在资源被拒绝后写入“已经取得资源”的权威状态。资源余额只在其所属模块保存，活动和主体通过引用读取。

资源占用跨模拟时刻存在时，需要显式预约、释放和到期规则。活动等待不占用 worker，但可能继续占用模拟中的资源；这两种占用分别记录。

## 5. 工具怎样与环境连接

| 工具类别 | 运行方式 | 记录和边界 |
|---|---|---|
| 只读模拟查询 | 读取当前 ActorView 或指定版本的授权投影 | 不读取更新中的实时状态 |
| 纯计算 | 在 worker 中计算 | 输入输出、算法版本及计算限额 |
| 产生模拟效果 | 返回 SimulationRequest，经提交后提供结果 | 工具成功返回请求不代表效果已经生效 |
| 外部检索 / MCP | 经适配器读取模型允许的资料 | 来源、访问范围、返回内容和实际时间 |
| 外部有副作用服务 | 独立效果适配器，在提交后由持久任务执行 | 幂等键、结果查询、失败与补偿规则 |

外部模型服务的网络访问与主体获取新资料分别配置。使用远端模型并不自动授予网页搜索、文件系统或外部数据库访问。

首版默认使用本地只读查询、纯计算和模拟效果工具。外部资料可由应用显式启用；真实外部写操作需要效果适配器通过恢复验收后再启用，不能与数据库提交假装成同一事务。

MAF 的工具和中间件是接入构件，模拟权限、数据范围与效果生效仍由这些合同确定。远端 Agent 接口也转换为同样的请求和反馈，见 [10](10-operation-and-observability.md#extensions)。

## 6. 环境扩展的验收

新增模块需交付状态 schema、操作定义、可见投影、冲突规则和小型示例。至少验证合法与非法参数、权限不足、资源争用、重复请求、到期事件，以及恢复后的状态一致。

这些检查证明组件按声明规则运行。规则是否适合现实研究对象，留给使用该组件的应用研究。
