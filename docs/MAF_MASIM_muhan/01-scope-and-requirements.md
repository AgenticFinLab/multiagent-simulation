# 01 · 范围、需求与设计原则

[返回总览](README.md) · 下一篇：[总体架构](02-architecture.md)

## 1. 系统要交付什么

建设面向模拟的通用基础设施，支撑大量持续主体与按需发生的局部活动。使用者通过组件和配置表达模型，系统负责按声明的时间、信息和后果规则运行，并提供扩展、恢复和检查能力。

| 使用者 | 提供的内容 | 获得的能力 |
|---|---|---|
| 模型作者 | 主体分布、行为、环境、关系、活动模板和时间规则 | 组合模型，运行并检查状态和轨迹 |
| 组件开发者 | 一种行为、环境能力、记忆机制或活动流程 | 通过稳定合同接入，复用执行与记录设施 |
| 运行维护者 | 计算资源、模型端点、配额、存储和保留策略 | 启动、监控、暂停、恢复及导出 |

模型输入与执行输入分别保存。增加 worker 通常属于执行配置变化；替换行为模型、修改消息延迟或压缩记忆属于模型变化。两者都记录版本，按不同标准检查其影响。

系统输出包括运行定义、主体与环境状态、活动进度、消息与行动处置、可恢复位置、模型用量及检查报告。真实领域材料、历史拟合和经验评价后续由应用研究提供。

## 2. 终态需求

| 编号 | 能力 | 系统应允许的具体行为 | 主要设计位置 |
|---|---|---|---|
| R1 | 持续主体与群体生成 | 按定义和分布创建大量主体，身份、记忆与关系跨活动保留 | [03](03-model-and-contracts.md)、[04](04-agents-and-memory.md) |
| R2 | 主体结构与异质行为 | 支持原子与复合主体，可组合规则、LLM 和工具；内部角色可保留状态并按有限层级嵌套 | [04](04-agents-and-memory.md) |
| R3 | 可组合环境与行动 | 多个环境模块提供能力、信息和行动后果 | [05](05-environment-and-actions.md) |
| R4 | 持续局部活动 | 主体按需发起、加入、协商、等待、退出与结束活动 | [06](06-activities-and-workflows.md) |
| R5 | 重叠参与与因果时间 | 同一主体参加多项活动；行动、消息和等待按声明规则生效 | [06](06-activities-and-workflows.md)、[07](07-time-and-communication.md) |
| R6 | 可扩展执行与受控成本 | 主体数量、活跃工作、worker 和模型并发分别配置与测量 | [08](08-execution-and-scaling.md) |
| R7 | 一致恢复 | 世界状态、局部流程、在途消息和计算结果按同一提交位置恢复 | [09](09-state-and-recovery.md) |
| R8 | 运行操作与过程检查 | 定位一次行为的输入和后果，查询、暂停、恢复及导出 | [10](10-operation-and-observability.md) |

## 3. 贯穿场景

采用虚构的资源共享社区说明系统使用方式。A、B、C 开展资源协商 X；协商期间，A 又与 D 开展合作 Y。两项活动持续的时间可以不同，也可能争用 A 可支配的同一资源。

在这个例子中，A 由计划、资源核对和协调三个内部角色共同决策。它们为 X、Y 分别维护局部会话，并按记忆规则保留长期经验。

主体可以报价、拒绝、修改需求、邀请成员、申请资源、等待或退出。环境负责验证资源和授权，结果可以成功、失败或没有效果。工程测试用受控响应覆盖这些分支，实际运行路径由所配置的行为组件决定。

这一场景用于检验独立行为、复杂协作、信息范围、资源竞争、延迟和恢复，采用合成规则，不作领域真实性或行为校准主张。

## 4. 关键问题与对应方法

| 问题 | 对应方法 | 主要代价 |
|---|---|---|
| P1 · 长期主体数量远大于同时执行量 | 状态独立存储，事件定位活跃对象，共享 worker | 状态装载、缓存和序列化 |
| P2 · 主体决策与协作的复杂度差异大 | 简单行为使用函数，复杂行为复用 MAF；主体内部结构单独配置 | 内部授权、状态隔离与版本管理 |
| P3 · 活动跨时刻等待且成员重叠 | 持续活动记录、模拟边界、请求—响应接续 | 等待索引、会话隔离与冲突处理 |
| P4 · 计算速度可能影响模拟顺序 | 固定阶段读取版本，收齐结果后按模型规则处理 | 慢任务会限制阶段推进 |
| P5 · 多方更新同一状态 | 明确字段归属，联合后果处理与事务提交 | 热点资源和提交吞吐 |
| P6 · 失败、重复调用和预算不足 | 稳定身份、尝试失效、共享配额和恢复协议 | 存储与运行管理成本 |
| P7 · 扩展策略可能改变模型含义 | 将执行优化与行为、信息变化分别配置和检查 | 需要受控比较，部分优化无法透明使用 |

## 5. 贯穿原则

1. **对象分工。** 主体、内部角色、活动、行为实例、worker 和模型端点分别拥有身份与生命周期。
2. **显式反馈。** 行为产生候选请求，联合处置协调环境、活动与主体规则，主体随后收到反馈。
3. **声明可见性。** 输入构造、记忆检索和消息传递遵循同一套信息规则。
4. **完整生效。** 活动进度与世界变化在明确的提交位置关联，失败不能留下无法解释的部分效果。
5. **按职责复用。** MAF 提供行为运行构件，MASim 提供适用资产，新系统补充模拟协调合同。
6. **用完整链路验收。** 既看是否执行成功，也检查下一次观察、恢复后状态和资源约束。

## 6. 建设范围

最终系统包含 R1–R8。实施从小型工程负载开始，逐步增加持续活动、分布式执行和故障恢复。扩展合同允许后续接入领域环境、外部知识与远端服务。

真实事件模拟、科学评价和模型训练由应用研究单独开展；EPG 作为后续轨迹输出适配。多租户平台、交互式编辑器、跨地域容灾和所有外部协议的完整产品化不作为基础设施首版的交付条件。

运行有效性指：系统执行符合声明的模型，状态、信息和因果关系可检查。领域假设是否合理、输出是否符合经验事实，需要后续研究另外建立证据。
