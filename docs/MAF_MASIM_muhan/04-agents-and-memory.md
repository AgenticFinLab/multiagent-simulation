# 04 · 主体、行为与记忆

[返回总览](README.md) · 前一篇：[模型与合同](03-model-and-contracts.md) · 下一篇：[环境与行动](05-environment-and-actions.md)

## 1. 主体怎样定义和长期存在

主体定义包括身份与角色、属性、行为、记忆规则、关系和生命周期。初始化可以来自显式配置或群体分布。状态保存于 RunStore，被激活时才装载所需部分；主体数量无须与 Python 对象、Ray Actor 或模型会话数量一一对应。

主体停用时，模型规定资源、活动、在途消息和内部角色的处置。活动结束释放局部执行资源，主体身份、允许保留的记忆与关系继续存在。

主体有两个独立的设计维度：

| 维度 | 选择 | 决定什么 |
|---|---|---|
| 内部结构 | 原子主体 / 复合主体 | 是否具有持久的内部角色与协调关系 |
| 行为机制 | 函数、规则、LLM、混合 | 每个决策单元怎样产生结果 |

原子主体也可以使用复杂工具循环；复合主体的管理者和子角色也可以全部由代码实现。结构复杂度与是否使用 LLM 分别配置。

## 2. 复合主体与内部子智能体

**复合主体（CompositeActor）**对外具有一个 actor_id，对内包含多个有稳定身份、私有状态和长期记忆的**内部子智能体（SubAgent）**。内部通过建议、讨论或委派形成结果，最终以父主体身份参与模拟世界。

实现上，ActorDefinition 绑定 CompositeBehavior，由后者组织内部角色并接入共享执行与调度。

| CompositeBehavior 的配置 | 需要明确的规则 |
|---|---|
| 内部角色 | subagent_id、职责、行为绑定、私有状态和记忆规则 |
| 角色结构 | parent/children 关系、角色路径、有限嵌套深度 |
| 输入与通信 | 每个角色可读字段、内部消息范围、允许的共享内容 |
| 局部执行 | 顺序、并行、委派或讨论，触发条件与计算上限 |
| 结果汇总 | 管理者决策、表决、否决或授权代表，以及冲突和失败处理 |
| 对外能力 | 哪些角色可代表父主体提出哪些请求，最终授权检查 |
| 生命周期 | 角色创建、停用、替换及其状态与待响应请求的处置 |

例如，主体 A 包含计划、资源核对和协调三个角色。计划角色提出方案，资源角色检查 A 可见的预算，协调角色根据声明策略选择或修改提议。各角色可以采用不同模型或函数；对外资源申请仍使用 A 的身份，并保留提出与汇总结果的 role_path。

管理者可以是代码、状态机或 LLM。LLM 管理者的判断也是候选结果，对外动作仍需通过确定的身份和权限检查。子角色权限不能大于父主体，也不能通过内部委派自行扩展。

终态支持有界嵌套和受控角色变化。长时间等待返回模拟边界；角色的创建、停用及持久授权变化在提交后生效。内部局部讨论无须为每句话推进模拟时间，需要建模耗时或等待世界结果时使用模拟请求。

## 3. 复合主体、群体和组织的区别

| 概念 | 表达的对象 | 身份与状态 |
|---|---|---|
| 原子主体 | 一个对外决策单元 | 一个 actor_id，无须内部持久角色 |
| 复合主体 | 多角色共同形成一个对外主体的行为 | 一个 actor_id；内部各有 subagent_id 与状态 |
| PopulationDefinition | 批量生成主体的数量、分布和关系 | 生成具有各自身份的原子或复合主体 |
| 组织关系 | 多个独立主体的隶属、协作与代表权 | 各成员保留自己的 actor_id |
| Activity | 一次持续协商或合作 | 独立 activity_id，保存参与关系与局部过程 |

成员若需要独立世界权限、对外通信、生命周期和个体轨迹，应建模为独立 Actor，并通过组织关系连接。内部层级用 parent/children 关系表达，PopulationDefinition 专用于群体生成。

多主体活动的参与者可以是原子或复合主体。活动中的可信调度节点只执行模板规则；具有自主判断的主持人必须声明其模拟身份或所属主体，以及允许看到的信息。

## 4. 行为的统一接入

FunctionExecutor 与 MAFExecutor 接收统一 ExecutionRequest，行为任务返回 SegmentResult。MAF 负责内部函数、Agent 和局部工作流的组合。

| 行为形态 | 执行方式 | 合同重点 |
|---|---|---|
| 数值或规则 | 普通函数、显式状态机 | 逻辑随机流、可恢复状态、请求与反馈 |
| LLM | MAF Agent + 结构化结果 | 输入、模型绑定、工具和输出校验 |
| 规则与 LLM 混合 | 函数与 Agent 节点组合 | 执行顺序、候选约束、失败行为 |
| 检索增强 | MAF Agent + 范围受控的检索 | 来源、权限、输入版本和调用记录 |
| 复合主体 | CompositeBehavior + 局部角色流程 | 持久角色、独立会话、结果汇总与对外授权 |
| 多主体活动 | Activity + WorkflowBridge | 成员身份、显式通信、模拟反馈 |

预算不足使运行等待或暂停，不自动把 LLM 角色改为规则角色。同一种 ActorDefinition 可以绑定不同机制；替换行为、模型、提示或汇总策略形成新的模型定义。

## 5. 两层记忆与接续状态

| 内容 | 唯一生效归属 | 更新与恢复 |
|---|---|---|
| 主体长期属性、记忆 | ActorState | 按主体规则提交，从状态版本装载 |
| 内部角色长期属性、记忆 | 父主体拥有的 SubAgentState | 独立角色范围，按父主体规则合并提交 |
| 活动共享记录 | ActivityState 关联内容 | 仅包含已生效的共享消息与活动信息 |
| 当前流程的成员及角色会话 | BehaviorInstanceState 关联的 checkpoint | 按实例、主体、角色隔离，随片段提交 |
| 当前流程的位置与未完成请求 | 同一 BehaviorInstanceState | 等待释放 worker，接续保持实例身份 |
| 临时推理与工具中间值 | 当前片段 | 默认暂态；需要持久化时声明去向 |

MAF Session 与 Context Provider 用来承载局部会话和装配上下文，长期角色状态由模拟状态合同管理。[MAF 会话与记忆](https://learn.microsoft.com/en-us/agent-framework/concepts/agents/conversations/)

同一角色在 X、Y 中保留共同的长期身份，分别使用 X、Y 行为实例内的局部会话。两项活动同阶段读取相同已提交长期状态；候选记忆更新按父主体的字段规则合并。X 中的信息只有经 MemoryPolicy 接受并提交，才可能在后续阶段进入 Y 的输入。

角色之间按声明的内部通信规则共享信息。父主体统一管理状态，各角色仍有各自的可见范围；适配层负责路由，模型与工具仅取得当前角色获准使用的内容。

一份会话只有一个恢复来源。嵌套工作流的局部状态归入顶层行为实例的 checkpoint；其中对长期状态仅保存版本引用，不能作为另一份可写的 SubAgentState。

## 6. 观察、检索与记忆计算

ObservationBuilder 在固定 state_version 和当前坐标下构造 ActorView：

1. 读取主体及内部角色身份、可见属性与环境投影。
2. 加入已经到达且允许该身份接收的消息与反馈。
3. 按 MemoryPolicy 执行固定版本的只读检索。
4. 装配该角色允许了解的能力、活动角色和工具描述。
5. 按声明依赖加入本阶段准备任务的已保存结果，并记录来源。

只读检索直接使用已保存内容；摘要、反思或重排若需要调用模型，则登记为机制任务（mechanism），在输入准备阶段（prepare）执行。计算结果可供指定主体或角色使用，长期记忆的写入仍经过 MemoryPolicy 和主体更新规则，在提交时生效。

需要行动反馈的反思安排在后续模拟阶段，待后果生效后再计算，从而保持输入准备、决策与反馈之间的依赖顺序。任务依赖和恢复方法见 [07](07-time-and-communication.md) 与 [09](09-state-and-recovery.md)。

记忆、检索、反思与规划的分工可参考 Generative Agents；具体机制、频率和压缩方式属于模型选择，其研究结果不直接证明本系统的行为有效性。[Generative Agents 论文](https://arxiv.org/html/2304.03442v2)

## 7. 灵活行为与活动参与

LLM 可选择行动对象、参数、顺序、沟通、等待与合作方式。环境能力与资源限制决定可执行范围，详见 [05](05-environment-and-actions.md)。

A 的内部角色可以共同生成 X 的方案，也可以在 Y 的独立会话中处理另一任务。各流程返回的动作都归于 A；共享资源冲突由联合处置解决，共享属性与记忆由父主体规则处理。运行时并发上限不代替注意力或工作时间建模。

仅依赖当前授权信息的内部协作可在一个片段完成；依赖其他主体或环境效果的路径保存请求与 checkpoint，接收新视图后继续。
