# 09 · 状态、提交与恢复

[返回总览](README.md) · 前一篇：[执行与规模](08-execution-and-scaling.md) · 下一篇：[使用与观测](10-operation-and-observability.md)

## 1. 持久化路线

PostgreSQL 保存版本化状态与事务记录，BlobStore 保存 checkpoint、大型输入输出及不可变载荷。先持久化载荷，再在数据库事务中提交引用。

状态变化、流程进度和后续事件在同一次提交中生效。数据库提供原子性，运行所有权、有效尝试和跨对象约束由应用协议实现。[PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html)

| 记录 | 必要内容 | 用途 |
|---|---|---|
| runs / bindings | 运行定义、ModelBinding 摘要、EndpointBinding、实际模型核对、当前版本、owner_epoch | 恢复身份与最近生效位置 |
| state_versions | 主体、子角色、环境、活动及行为实例的版本状态或引用 | 固定读取、字段归属及接续位置 |
| phases / stage_tasks | 坐标、读版本、事件、阶段规则、封存任务与依赖、输入引用 | 重建完整阶段及后续工作 |
| attempts / candidates | 尝试身份、有效性、结果摘要、选中与封存记录 | 复用上游结果，排除迟到候选 |
| requests / responses / deliveries | 来源、等待映射、响应身份、投递与消费处置 | 部分接续、去重及迟到反馈 |
| commits / events | 处置摘要、模块更新、后续事件、派发状态 | 确认效果及重新派发 |
| calls / reservations | 模型绑定、实际调用、预留、用量与 unknown 状态 | 费用归因与配额恢复 |
| blobs | 内容摘要、大小、格式、可达引用 | 跨 worker 装载与完整性检查 |

这是逻辑记录设计，物理表和索引在实现时确定。恢复所需关系完整保留，诊断采样不能替代。

## 2. 固定版本与接续位置

SnapshotView 按 state_version 装载长期状态；BehaviorInstanceState 指向该版本生效的 checkpoint。ActorState 和 ActivityState 只关联实例身份。SubAgentState 属于父主体的长期状态，局部会话属于实例，两者分别检查。

任务派发前保存授权输入与依赖引用。执行过程中不查询最新可变状态；接续任务使用本阶段的新视图、原局部会话和有效反馈。输入准备任务的派生结果单独保存，与已提交状态区分。

参考实现采用版本记录和不可变载荷。只保存最新值的表无法支持过去的读取版本。所有在途任务、封存候选、待接续实例、长期状态和保留回放记录都是内容回收根。

## 3. 一次阶段提交

1. **登记阶段。** 固定 phase_id、读版本、到期事件和工作阶段规则；创建行为实例等候选也保存在计划中，不提前进入模拟状态。
2. **封存任务输入。** 按 prepare、behavior、adjudicate 的依赖生成任务集合。每批派发前持久保存任务、输入和上游候选身份；已有任务集合不能被重启重新解释。
3. **保存并选择候选。** worker 保存完整结果与 checkpoint；协调进程检查身份、版本和完整性。上游结果用于生成下游任务前，先持久封存唯一选择。
4. **确定处置与更新计划。** 收齐全部必需结果后生成 DispositionPlan，环境、活动、主体、行为实例和消息计划引用同一处置。此过程只消费保存的结果和固定随机流。
5. **事务生效。** 核对 owner_epoch、expected_version、封存任务与选中尝试，写入状态、处置、响应消费、等待关系、接续位置、投递和后续事件。
6. **继续执行。** 返回 CommitReceipt，从已提交事件派发下一阶段。

数据库以 commit_id、请求及逻辑投递身份等唯一约束防止重复生效。同一 commit_id 再提交时，内容一致返回已有回执；不同则报冲突。

任务登记、调用账目和候选封存属于运行记录，不改变 state_version。响应消费记录与新的流程进度共同提交，恢复时二者始终对应。

过程记录与状态在同一提交中保存必要关联。指标允许随后补发，指标服务故障不会丢失恢复依据。

## 4. 所有权、选中候选与重试

每个 run 只有一个有效协调所有者。新实例取得更高 owner_epoch，旧实例无法继续提交或取得新任务与模型调用许可。

每个 task_id 至多选中一个有效 attempt。完整候选可在核对后接纳并保存选择，无须一律重算。**一旦候选被下游任务引用，就不能在恢复中换成另一份非确定性结果。** 已封存载荷缺失或损坏时暂停并报告，不能静默再次调用模型填补。

尚未选中的失败任务可以按策略重试；再次外部调用生成新 call_id 并保留费用。系统去重的是已提交逻辑效果，外部调用可能重复。

Ray 进程重启和方法重试服从相同身份协议，不能绕过 ModelAccess、候选选择和效果去重。只有事务状态确认后，才能决定从哪个位置恢复。

## 5. 故障恢复矩阵

| 中断位置 | 恢复动作 | 必须检查 |
|---|---|---|
| 计划已登记、任务未派发 | 按封存清单补派发 | 输入、依赖和读版本不变 |
| 上游已选中、下游尚未派发 | 复用上游结果生成或装载下游清单 | 来源摘要一致，不重抽模型结果 |
| worker 执行中、结果未保存 | 核对调用后重试未选中任务 | 旧尝试失效，unknown 有记录 |
| Blob 已写、候选未登记 | 核对可识别结果，或按规则回收 | 无未提交内容成为世界状态 |
| 全部候选已登记、提交前 | 重建相同联合处置和更新计划 | 必需任务完整，所有者有效 |
| 事务已提交、回执丢失 | 按 commit_id 查询回执 | 相同内容不重复生效 |
| 提交后、后续派发前 | 从事件表继续 | 消息与任务去重 |
| 独立或活动实例等待中 | 装载生效接续位置与当前 ResumeInput | 原请求、部分响应和角色视图完整 |
| 角色停用或活动取消后收到反馈 | 保存迟到处置 | 不恢复已结束路径或扩大权限 |
| 旧协调实例继续运行 | 拒绝旧代次写入 | 不出现第二条提交序列 |

运行的恢复位置由提交记录确定，并据此关联任务、消息和 MAF checkpoint。

## 6. MAF、嵌套会话与响应恢复

每个行为实例提交定义版本、continuation_ref、待请求集合、binding_version_refs 与会话完整性摘要。恢复先核对原 checkpoint 对应的绑定；若成员或角色随后发生已提交变化，再应用 control_event_refs，使它与当前 ActivityState、ActorState 对齐。未记录的差异视为恢复错误。

嵌套子流程的局部状态和请求映射从顶层 checkpoint 恢复，长期角色状态从父主体的状态版本读取。MAF 中间检查点属于候选记录，只有已提交行为实例指向的引用具有生效含义。

接续时构造包含当前视图、有效响应和控制输入的 ResumeInput，在 Bridge 内过滤重复与迟到响应，再按原 MAF 请求标识恢复。部分响应只推进相应路径；其余 pending 继续保存。角色停用等变更需要的取消映射保留至清理完成，普通迟到答复不进入该路径。响应及控制事件的新消费记录与 checkpoint 在下一次提交中一起生效。

会话恢复失败时停止接续，不使用空会话。图结构、executor 身份、序列化和依赖版本须可重建；模板升级需要迁移。新观察注入及 SDK 限制见 [06](06-activities-and-workflows.md#bridge)。

## 7. 暂停与配置核对

| 状态或操作 | 行为 |
|---|---|
| 正常暂停 | 优先完成本阶段提交，停止进入下一阶段 |
| 部分阶段暂停 | 保存任务、候选及依赖，保持原读版本 |
| 恢复 | 核对定义、模型绑定、调用账目、输入和接续位置，继续未完成工作 |
| 强制停止 | 失效在途尝试，保留可解释的恢复位置 |
| quiescent | 无可推进事件，但仍有等待或允许的外部输入 |
| completed | 模型终止条件、必需清理和记录均已提交 |

部分阶段暂停不提交已完成任务的部分世界后果。恢复复用有效候选，包括已完成的摘要、反思及环境判断；数据库重试不重新触发这些调用。

ModelBinding 的模型、可用 revision 和解码设置属于运行定义。恢复可以更换 worker、连接地址或凭据，但须核对它们仍服务原绑定；同名 deployment 不证明模型相同。无法核对的 revision 保存 declared_only 状态，明确版本核验的限制。

模型或解码配置发生变化时，建立新的运行定义，必要时通过显式状态迁移开始新 run。实际依赖和 provider 适配行为也纳入兼容检查，详见 [08](08-execution-and-scaling.md#model-binding)。

## 8. 恢复、回放与重算

恢复检查中断后能继续已承诺的状态序列。记录回放读取初态、提交变化和保存的外部响应，重建状态并核对后果。重算验证则再次执行确定性组件比较结果。

回放不重新发起外部副作用，也不要求重新调用真实模型得到相同文字。不可查询的外部效果保持 unknown。科学复现与领域有效性由应用研究另行建立证据。
