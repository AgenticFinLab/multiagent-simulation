# 10 · 软件工程 / 任务型多智能体（补充）

> 这一类是“多智能体协作”的另一大流派：用 SOP / 对话链 / handoff 组织少量专家 agent 完成一个复杂任务。对我们的价值在于**复合 agent 内部编排**，而非规模。

## 1. MetaGPT（软件公司 SOP）

- 核心哲学：**Code = SOP(Team)**——把“软件公司”装进框架。
- 角色：产品经理 / 架构师 / 项目经理 / 工程师，按精心编排的 SOP 协作。
- 输入一行需求，输出 PRD / 设计 / 任务 / 代码仓库。
- 关键机制：**消息总线 + SOP 约束的角色**，让每个角色只消费上游对应输出。
- 启示：**“标准作业程序”把团队协作变成可复用流水线**——正是复合 agent 需要的“可预期编排”。

## 2. ChatDev（ChatChain 对话链）

- 核心：**ChatChain**——把协作编排成一条链，每个节点是**两个角色的对话**（CEO↔CTO、程序员↔测试）。
- 流程借鉴软件工程瀑布模型：设计 → 编码 → 测试 → 文档。
- 启示：**“两两对话 + 链式推进”** 是比“群聊”更可控、更便宜的协作方式。

## 3. OpenAI Agents SDK / Swarm（handoff 交接）

- Swarm（2024，实验）把多 agent 编排蒸馏为两个原语：**handoff（交接）+ routines（例程）**。
- Agents SDK（2025，生产继任者）保留 handoff，并加**session 管理、guardrails、tracing**。
- handoff 实现为一种“特殊工具调用”：模型判断该移交时调用 `transfer_to_XXX`，把控制权交给另一个 agent。
- 启示：**“交接”是复合 agent 中“由一个子 agent 交给另一个子 agent”的最小、干净原语**。

## 4. AgentVerse（多智能体环境框架）

- 核心：把多智能体环境拆成**五类可自定义模块**（环境、描述器、顺序、agent、记忆等）。
- **Order 顺序**：random / sequential / concurrent（每轮全体行动）可配。
- 四阶段：专家招募 → 协作决策 → 行动执行 → 评估。
- 启示：**“环境/顺序/描述”模块化** 与“concurrent 每轮全体行动”正是模拟器需要的能力（MASim 已具备类似拓扑层级）。

## 5. AutoAgents（自动生成 agent）

- 核心：**Drafting（起草）→ Execution（执行）** 两阶段，先自动生成一组 agent 与计划，再执行。
- 强调生成 agent 的**可靠性**。
- 启示：**“按任务自动生成 agent 团队”** 可用于 10⁵ 规模下“按需生成角色”的场景（但要节流）。

## 6. 本类共性

| 系统 | 协作原语 | 适合 | 给复合 agent 的启示 |
|------|----------|------|---------------------|
| MetaGPT | SOP + 消息总线 | 可预测流水线 | SOP 化复合 agent |
| ChatDev | ChatChain 两两对话 | 链式任务 | 两两对话更省 token |
| Agents SDK | handoff | 控制权移交 | 最小组件交接 |
| AgentVerse | 模块化环境+Order | 环境类实验 | 顺序可配置 |
| AutoAgents | 自动生成+执行 | 动态团队 | 按需生成角色 |

**结论**：这些是“复合 agent 内部如何组织子 agent”的现成素材，但都不解决“世界推进 + 大规模”。与 D1/D2 决策一致：它们应作为复合引擎的内部实现候选，而不是整体架构。
