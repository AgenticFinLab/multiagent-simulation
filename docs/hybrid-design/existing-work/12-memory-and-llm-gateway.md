# 12 · 记忆管理与 LLM 网关（补充基础设施）

> 这两块不是“模拟器”，但直接决定我们“规模化 + 成本控制”能不能落地。

## 1. MemGPT / Letta（分层记忆 + 虚拟上下文）

- 核心思想：把 LLM 上下文窗口当成操作系统管理 RAM——**虚拟上下文（Virtual Context）**。
- 记忆分三层：
  1. **Core Memory**（核心记忆，常驻上下文，2–4K token，agent 可自编辑）；
  2. **Working/Agent Memory**（工作记忆，像 OS 分页一样在主/外部之间换页）；
  3. **Archival Memory**（归档，长期存储，检索式访问）。
- 三种操作：**Paging（分页换入换出）、Summarization（压缩旧记忆）、Retrieval（检索）、Eviction（满时淘汰）**。

### 启示
- 这正是我们“冷/温/热三级状态”的**agent 侧实现**：核心记忆常驻，历史归档检索，满则淘汰/压缩。
- 10⁵ 规模下，每个 agent 不能把全历史塞进 LLM 上下文，必须用“分页 + 摘要 + 检索”。

## 2. LLM 网关（LiteLLM / Portkey / Kong AI）

- 定位：统一代理层，把“模型供应商、限流、配额、缓存、可观测、鉴权”集中管理。
- 关键能力（与我们强相关）：
  - **路由**：多供应商、模型分级（小模型干简单活、大模型干难活）；
  - **限流 + 配额**：per-key / per-team / per-tenant 预算，防止失控；
  - **缓存**：prompt / 语义 / 结果缓存；
  - **fallback / retry**：供应商失败切换；
  - **成本归因**：每 key/团队的花费记账；
  - **可观测**：token/延迟/错误 trace。

### 启示
- **我们不需要自研 LLM 网关**，直接复用 LiteLLM/Portkey 这类现成层，把 B1（成本/限流）外包给成熟组件。
- 我们只做“调度策略 + 降级链 + 配额规则”这些**上层策略**，下层转发交给网关。

## 3. Serving 上下文（vLLM / SGLang，仅供定位，不纳入设计）

- 这是“LLM 推理加速”层，**明确不在我们设计范围**（讨论点：不解决无法自行解决的部分）。
- 仅作为“模型端点”的背景：我们假设存在可横向扩展的 serving + 网关，只关心其外部属性 `latency / throughput / rate-limit / cost`。

## 4. 结论

| 层 | 方案 | 我们做什么 / 不做什么 |
|----|------|----------------------|
| 记忆 | MemGPT/Letta 范式 | 借用“分页/摘要/检索/淘汰”做冷热分层 |
| 网关 | LiteLLM/Portkey | 复用；我们只写调度策略/降级/配额 |
| serving | vLLM/SGLang | 不碰；视为黑盒端点 |
