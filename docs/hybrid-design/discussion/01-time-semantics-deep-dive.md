# 01 · 时间语义的深入讨论（对应讨论点 3）

> 问题：世界按什么节奏推进？三种候选：同步时间步 / 事件驱动 / 异步。这里把它们放在“金融模拟 + LLM 延迟差异巨大”这个前提下讨论。

## 1. 为什么这是个“关键问题”

同一个系统里，两类操作的耗时差 3~6 个数量级：

```text
规则 agent 决策    ≈ 微秒 ~ 毫秒
市场撮合           ≈ 毫秒
LLM 决策           ≈ 秒级（且抖动大，可能超时）
```

如果世界推进“等最慢的那个 LLM”，一轮 = 最慢 LLM 的时间，吞吐被拖垮。所以时间语义的核心矛盾是：**可复现（要顺序、要屏障）vs 吞吐（不能空等慢 LLM）**。

## 2. 三种候选

### 2.1 同步时间步（time-stepped，屏障式）
- 每轮一个同步屏障：所有 agent 都完成、消息都投递，才进入下一轮。
- 优点：**顺序确定、可复现、可 checkpoint、好调试**。
- 缺点：**一轮耗时 = 最慢者**；LLM 抖动直接拖垮整体。

### 2.2 事件驱动（event-driven）
- 只在有事件时推进（如新闻、成交、订单）。
- 优点：省算力、贴真实（市场本来就是事件驱动）。
- 缺点：**事件顺序依赖调度时序，难以复现**；并发事件需要复杂的因果/时间戳协议。

### 2.3 异步（async，agent 各自推进）
- agent 独立推进，不设全局屏障。
- 优点：吞吐最高。
- 缺点：**强非确定**，市场撮合的一致性与可复现都很难保证。

## 3. 推荐方案：同步时间步 + 低频决策/高频执行 + 截止降级

保留“同步屏障”带来的可复现，但把“慢 LLM”从关键路径上挪走。

### 3.1 三层时间结构

```text
轮 round（同步屏障，可 checkpoint）   ← 可复现的基本单位
  └ 层 level（拓扑层级，同层并行、跨层串行）  ← 因果顺序（MASim 已有）
       └ 决策 decision（LLM 低频决策，产出意图；执行层高频用意图）
```

### 3.2 低频决策 + 高频执行（不是“预测未来”）
- LLM 只在“它做决策那一刻有真实观察”时决策（例如每 N 轮一次），产出一个“意图/策略”。
- 两次决策之间，规则执行器按该意图机械执行，不再调 LLM。
- 后台可异步刷新新意图；刷新完成前继续用旧意图（容忍“意图略微陈旧”）。
- 第 `t` 轮屏障时：LLM 结果已就绪的用 LLM；没就绪的走降级。

### 3.3 截止 + 降级（deadline + degradation）
- 每个 LLM 决策有 `deadline`（如 2s）与降级链：
  ```text
  LLM 就绪 → 用 LLM
  LLM 超时/限流/超预算 → 用缓存 → 用 RuleLLM → 用 Rule（默认/跟随）
  ```
- 世界**永远前进**，不被个别慢 LLM 卡死。

### 3.4 可复现性补偿
- 即便异步，结果仍按 `(round, level, agent_id, seq)` 落盘，**逻辑顺序**与同步一致。
- 固定 `temperature`；记录 `model/version/prompt_hash`；缓存命中可复算。

## 4. 三种方案的选择结论

| 场景 | 推荐 |
|------|------|
| 默认（研究/回测/校准） | 同步时间步 + 低频决策/高频执行 + 截止降级 |
| 高频市场微观结构 | 同步时间步内的事件驱动撮合（CDA 逐 tick） |
| 纯规则/无 LLM 的大规模 | 同步时间步（屏障代价可忽略） |
| 交互式实时推演 | 事件驱动 + 松一致性（放弃严格可复现） |

**关键判断**：可复现是金融研究的底线，因此“同步屏障”保留；吞吐靠“低频决策 + 高频执行 + 截止降级”解决，而不是牺牲可复现。MarketSim 的“战略/执行解耦”本质也是同一个思想——**慢决策与快执行放在不同时间尺度**。

## 5. 需要你拍板的两个子问题

1. **意图陈旧容忍度**：执行层用“上一次意图”时，若市场已变化较大，允许“意图略微陈旧”吗？（我倾向：允许，但加 `staleness` 上界，超界则降级到规则/立即刷新。）
2. **默认 deadline**：LLM 决策默认给多少秒/轮？（取决于模型与批处理，我建议先 2~5s 可配置，再实测标定。）
