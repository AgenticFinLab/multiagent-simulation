# 03 · 平台定位修正：纯通用基础设施，无任何领域层

> 回应讨论点 1（最终版）：**平台里没有“金融领域层”，也没有任何领域层。平台是纯通用基础设施，金融/社会等由使用者自行实现。**

## 1. 最终定位（取代上一版“金融领域层”的提法）

**平台 = 一个领域无关的、通用且灵活的“多智能体模拟基础设施”。**

- 平台只提供**通用原语与机制**，不内置任何具体领域的语义（没有市场、没有订单、没有社交、没有疫情）。
- **做金融还是做社会，是“使用者”的事情**：使用者用平台的通用原语去**自己实现**撮合、订单簿、社交关系、传播规则、指标等。

```text
平台（基础设施，我们提供，领域无关）
  ├─ Agent 抽象（统一递归契约）
  ├─ 激活控制器（谁这一轮需要行动）
  ├─ 逻辑时间推进（round/level，同步屏障）
  ├─ 拓扑 / 层级（谁与谁交互）
  ├─ 通信总线（内部消息） + 协议桥（A2A/MCP/AG-UI）
  ├─ 状态存储（冷/温/热、快照、隔离）
  ├─ 规模策略（异构引擎、缓存、降级、配额）
  └─ 可观测 / 审计

使用者（用平台原语自己实现）
  ├─ 具体 agent 行为（规则/LLM/RAG/复合）
  ├─ 具体世界规则（市场撮合、订单簿、社交网络、传播…）
  ├─ 具体消息语义（订单、帖子、评论…）
  └─ 具体指标与分析（金融指标、社会指标…）
```

## 2. 为什么这样更对

1. **平台才真正“通用、全面”**：没有任何领域假设，任何“大量 agent 交互”的场景都能装进来。
2. **职责清晰**：我们做“机制”，使用者做“内容与规则”。
3. **MASim 的既有代码不污染平台**：MASim 里那些金融专属部分（market/order/coordinator/金融指标），在平台视角下都降级为**“一个使用示例（user-land example）”**，就像现在 `examples/{Scenario}/` 一样，不属于平台内核。

## 3. 一个关键推论：MASim 的“金融内核”要一分为二

| 现有 MASim 部分 | 平台视角归属 |
|----------------|--------------|
| GeneralSimulator / 四阶段 / 拓扑层级 | 平台基础设施（通用） |
| PlayerPersona / Player / 通信 / 状态 | 平台基础设施（通用） |
| 市场撮合 / 订单簿 / CDA / 金融指标 | **使用者的金融示例，不进平台** |
| finance/market/opinion archetype | **使用者的金融示例，不进平台** |

也就是说：**平台的“世界内核”只到“时间 + 拓扑 + 通信 + 状态”为止；市场是使用者挂上去的领域逻辑。**

## 4. 这对“价值位定位（I10）”的最终表述

> 我们做的是一个**领域无关的通用多智能体模拟基础设施**：提供 agent 抽象、激活、逻辑时间、拓扑、通信、状态、规模降级、标准协议与可观测；**具体做金融、社会还是别的，由使用者实现**。
> 金融（继承 MASim 经验）是它的**第一个、也是最成熟的参考示例**，但不是平台的组成部分。
