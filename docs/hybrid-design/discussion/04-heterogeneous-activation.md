# 04 · 激活控制器（Activation Controller）——平台的一个基础设施模块

> 回应讨论点 2：把“异构激活”从“一个策略”提升为“平台的一个机制/模块”。
> 你的判断很准确：**每个 agent 都可能接收一个“激活信息”，系统有一个“激活模块/控制器”来统一管理这件事。**

## 1. 定位：激活是平台的一等模块

平台不预设“金融/社会谁该活跃”，只提供一个通用机制：

```text
激活控制器 ActivationController（平台模块，领域无关）
  ├─ 收集：每个 agent 注册一个 ActivationPolicy（可插拔、可组合）
  ├─ 决策：每轮/每层，按 policy + 环境上下文 判定“哪些 agent 被激活”
  └─ 下发：向被激活的 agent 发 ActivationSignal（激活信号）
```

- **激活信号**是一个通用数据结构，与领域无关，例如：
  ```text
  ActivationSignal(round, level, agent_id, reason, budget, deadline)
  ```
- agent 收到激活信号 → 执行决策；没收到 → 走默认/规则/上一轮（不调 LLM）。

## 2. 为什么“激活”要独立成模块

1. **规模控制的核心就在这一层**：控制“每轮有多少 agent 真正决策”，就控制了 LLM 调用量。
2. **领域无关**：金融的“价格异动触发”、社会的“被@触发”、疫情的“感染触发”，只是 policy 不同，模块不变。
3. **可观测**：每轮激活了多少、为什么激活、预算多少，都能从这里记账。

## 3. ActivationPolicy（可插拔的策略）

```text
ActivationPolicy(agent, round, context) -> Activate(reason, budget) | Skip
```

- 策略只决定“是否激活 + 给多少预算”，**不决定“怎么做决策”**（那是 DecisionEngine 的事）。
- 可组合的四类触发器（先给这四类默认实现）：
  1. **周期（periodic）**：每隔 K 轮激活（做市商每 tick、长线投资者每周）。
  2. **事件（event）**：环境事件命中即激活（新闻、跳空、被@）。
  3. **阈值（threshold）**：某个量超过阈值才激活（注意力预算：重要性 > τ）。
  4. **随机（stochastic）**：按概率激活（噪声交易者、泊松冲动）。
- 策略可叠加（AND/OR），例如「周期 OR (事件 AND 阈值)」。

## 4. 组节律（group rhythm）也挂在激活模块上

- 每个 group 可绑定一条**活跃度曲线**（over 逻辑时间），作为“随机/周期”激活概率的乘子。
- 表达“开盘活跃、盘中钝化、尾盘集中”“白天/夜间”这类节律。

## 5. 抽样也由激活控制器统一管

- 当“该激活的 agent 太多”时，控制器按**分层抽样**（按角色/组，小群体保底）再筛一遍，只对样本发“真正调 LLM”的激活信号；其余发“低预算/跟随”信号。

## 6. 与其他模块的边界（避免职责重叠）

| 模块 | 管什么 | 不管什么 |
|------|--------|----------|
| ActivationController | 谁这轮行动、给多少预算 | 怎么决策 |
| DecisionEngine | 观察 → 决策/行动 | 谁该动 |
| MessageBus | 消息怎么传 | 谁该动 |
| Scheduler（逻辑时间） | 什么顺序推进 | 谁该动 |

一句话：**激活控制器 = “决定谁现在需要思考”的调度器；决策引擎 = “思考本身”。**
