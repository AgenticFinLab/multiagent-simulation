# 01 · 场景与需求深度分析

## 1. 我们要支持的是什么

一句话：**一个“金融市场 + 群体行为”的通用模拟环境，agent 规模从几十、几千到几十万，每个 agent 可能是纯代码、LLM 驱动、或包含多个 sub-agent 的复合体。**

这和 MAF 的定位形成互补：

- MASim 已经解决：**世界如何运转**（市场撮合、时间推进、拓扑、通信、状态、Ray 分布式、实验产物）。
- MAF 已经解决：**单个/多个 agent 如何被定义、编排、暴露为服务**（Agent/Workflow/Harness、A2A/MCP/AG-UI、session/isolation、middleware/telemetry）。

混合架构要解决的：**在同一个世界里，让“代码 agent、LLM agent、复合 agent、外部 agent”以标准方式共存，并让规模跨越 10² → 10³ → 10⁵。**

## 2. Agent 光谱（agent 的五种形态）

| 形态 | 决策来源 | 延迟 | 成本 | 典型用途 |
|------|----------|------|------|----------|
| A. 纯代码/规则 agent | 确定性逻辑（如 MASim `CanonicalRulePlayer`） | 微秒~毫秒 | 几乎为零 | 做市商、套利、噪声交易者、市场微观结构 |
| B. LLM agent | 每轮调用 LLM（如 `CanonicalLLMPlayer`） | 秒级 | 高（token） | 需要语义推理的投资者、意见领袖 |
| C. 混合 RuleLLM | 规则先约束、LLM 在契约内决策 | 秒级 | 中高 | 可解释 + 可控的策略型 agent |
| D. RAG agent | LLM + 外部知识检索 | 秒级+检索 | 中高 | 依据论文/新闻/政策决策 |
| E. 复合/sub-agent agent | 内部多个子 agent（可能混合 A–D） | 视内部而定 | 视内部而定 | 基金公司 = 分析师+风控+交易员；监管者 = 监测+决策+执行 |

关键洞察：**这五种形态在规模上不是均匀分布的。** 规模越大，A 类占比必须越高，B/D/E 类只能用于“少数活跃者”或“抽样子集”。这是后文所有规模设计的出发点。

## 3. 规模等级与对应特征

| 等级 | 数量 | 现实约束 | 对系统的核心要求 |
|------|------|----------|------------------|
| L1（几十） | 10¹~10² | 可全 LLM，逐 agent 可查 | 高保真、低延迟、强可观测、交互式调试 |
| L2（几千） | 10³ | 全 LLM 会触发 rate limit 与成本爆炸 | 分组、异步、批处理、缓存、抽样 |
| L3（几十万） | 10⁵ | 绝大多数不能调 LLM | 规则/行为/向量为主，LLM 只做活跃子集，层次聚合 |

判据（粗略量级，用于指导配比，非硬性数字）：

- 若一次 LLM 决策 ~1s、token 成本 c，则 10⁵ 个 agent 每轮全调 LLM 意味着 10⁵ 次调用/轮，无论延迟还是成本都不可接受。
- 因此 **LLM 调用总量必须是一个受控变量**：`LLM_calls_per_turn = f(活跃比例, 抽样率, 分层压缩率)`，而不是 `N`。

## 4. 交互模式

1. **中心化市场交互**：所有交易者 → 市场撮合（MASim 已有 coordinator / maker-taker）。这是**扇入型**，天然可聚合。
2. **点对点通信**：agent ↔ agent（意见传播、消息、信号）。这是**潜在 O(N²) 的扇出型**，是规模化的主要敌人。
3. **广播/订阅**：市场行情、新闻、公告 → 全体/群体。
4. **分层聚合**：sub-agent → parent → group leader → hub（复合 agent 与分组的本质）。
5. **外部交互**：外部真实服务 / 人 / 其他框架 agent 通过协议接入（A2A/MCP/AG-UI）。

## 5. 生命周期与时间语义

- **回合（round/turn）**：MASim 的轮次，推进价格与状态。
- **步（step）**：一个回合内的多次决策（`steps_per_turn`）。
- **拓扑层级（level）**：同层并行、跨层串行，决定因果顺序（coordinator 先撮合还是投资者先下单）。
- **异构时间尺度**：市场撮合可能逐 tick，而 LLM 决策可能“每天/每事件才做一次”。MarketSim 的教训是**把战略推理与高频执行解耦**——这正是我们要借鉴的。

时间语义的两种推进方式：

- **同步时间步（time-stepped）**：每轮同步屏障，简单、可复现、可 checkpoint。
- **事件驱动（event-driven）**：按事件推进，省算力但难复现。
- 推荐：**同步时间步为主 + 慢决策异步预取**（见 `08`、`09`）。同步保证可复现，异步预取保证 LLM 延迟不阻塞世界推进。

## 6. 状态与记忆

- **即时状态**：cash、position、价格等（每 agent 必存）。
- **短期记忆**：最近 N 轮观察/消息（HistoryBuffer）。
- **长期记忆**：跨轮/跨场景的知识、经验（向量库或对象存储）。
- **复合 agent 状态**：父 agent 的状态是其子 agent 状态的函数 + 自身状态。

## 7. 评估与实验目标

- 复现 stylized facts（波动聚集、胖尾、动量/反转等）。
- 可复现（同 seed 同结果，至少对规则路径确定；LLM 路径需温度控制与缓存）。
- 可扩展（算力/成本可控）。
- 可审计（任何 agent 的决策可溯源：输入观察 → 引擎 → 输出行动）。

## 8. 对设计的直接推论

1. 需要一个**统一 Agent 抽象**，把五类形态包进去（否则复合与异构无法组合）。
2. 需要一个**可插拔决策引擎**层（规则 / LLM / RAG / 复合），世界引擎不感知“你怎么决策”。
3. 需要一个**分层的消息与聚合**机制，避免 O(N²)。
4. 需要一个**受控的 LLM 调用预算**与降级机制。
5. 需要一个**标准协议边界**（A2A/MCP/AG-UI），让子 agent、外部 agent、工具以统一方式接入。
6. 需要一个**状态/快照/幂等**体系，支撑几十万 agent 的断点续跑与可观测。

以上六条，直接映射为后文 `04` 的六层架构与 `05`/`06`/`07` 的具体设计。
