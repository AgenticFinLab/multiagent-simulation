# 11 · 开放问题、决策点与演进路线图

## 2. 关键决策点（建议先定）

1. **接口冻结**：先把 `AgentRuntime / DecisionEngine / MessageBus / StateStore` 四个接口定为 v1，其余围绕它演进。
2. **规模策略默认值**：先用 L1 默认（全保真）保证不破坏现有 MASim 行为，L2/L3 作为显式 opt-in。
3. **协议边界**：内部不走 A2A/MCP；只有“跨系统/跨语言/外部”才走协议，避免过度设计。
4. **LLM 网关**：先做一个薄的“批处理 + 缓存 + 降级 + 配额”网关，底层继续用 MAF chat client，不重复造 serving。
5. **兼容优先**：四阶段、三层消息、`on_fill` 契约、`topology.yml` 保持不变，新增能力走插件/适配层。

## 3. 主要风险与应对

| 风险 | 后果 | 应对 |
|------|------|------|
| 过度设计（为 10⁵ 而牺牲 L1 体验） | 几十个 agent 反而复杂 | 规模策略默认 L1；高级能力 opt-in |
| 聚合失真 | leader 代表成员丢掉关键行为 | 聚合 schema 保留统计 + 离群样本；小规模全量对照 |
| 语义缓存破坏异质性 | 行为趋同，stylized facts 失真 | 缓存命中与多样性指标联动；可关闭 |
| 异步预取引入不确定性 | 可复现性下降 | 结果按逻辑顺序落盘；固定温度 + 缓存 |
| 协议边界不清晰 | 内部误用外部协议拖慢性能 | 明确决策表（见 `07` §5） |
| 成本失控 | 实验费用爆炸 | 每 agent/group/租户配额 + 熔断 |

## 4. 分阶段演进路线图

### Phase 0（确认 + 接口定型）
- 冻结四个接口 v1；写 2~3 个代表性复合 agent 用例；确认与 MAF 的边界。
- 产物：`AgentRuntime` / `DecisionEngine` / `MessageBus` / `StateStore` 的契约文档 + 最小骨架。

### Phase 1（L1 全保真打通，不改变现状）
- 把现有 Rule/LLM/RuleLLM/Rag 四机制适配到统一 `DecisionEngine`。
- 引入 `AgentRuntime` 包装 `GeneralPlayer`，保证行为不变。
- 产物：L1 行为与现有 MASim 对齐（回归测试通过）。

### Phase 2（复合 agent + 协议桥，规模仍 L1/L2）
- 引入 `CompositeEngine`（先走 MAF Workflow / Harness）。
- 引入 A2A/MCP 协议桥，验证“远端子 agent”与“外部工具”接入。
- 产物：一个“基金公司复合 agent”端到端 demo，含远端 A2A 子 agent。

### Phase 3（分层聚合 + 规模策略，冲向 L2 几千）
- group + leader、兴趣路由、聚合消息。
- LLM 网关：批处理 + 三级缓存 + 降级 + 配额。
- 产物：L2 规模基准（几千 agent 的墙钟/成本/保真对照）。

### Phase 4（L3 几十万）
- 冷存储为主、压缩记录、采样溯源、多租户隔离、成本熔断。
- 规则/行为为主 + 抽样 LLM 的规模配比。
- 产物：10⁵ 规模的压力测试与 stylized facts 验证报告。

### Phase 5（治理与生态）
- 分层可观测面板、成本归因报告、实验发布包标准化。
- 与 `simulation-results/`、分析/评估体系打通。

## 5. 成功判据（可量化）

1. **行为一致**：L1 混合架构结果与现有 MASim 对齐（指标误差在容忍带内）。
2. **规模**：L2（10³）可交互运行；L3（10⁵）可批量运行，且成本/时间可预测。
3. **成本**：同等规模下，LLM 调用数与 token 量相比“全量 LLM”显著下降（缓存 + 抽样 + 分层），并可用 `cost/turn` 量化。
4. **可恢复**：任意轮中断后能从 checkpoint 续跑。
5. **可互操作**：一个复合 agent 能被 A2A 远端调用；一个 MCP 工具能被内部 agent 使用。
6. **可审计**：关键 agent 的任意决策可溯源到“观察 → 引擎 → 行动”。
