# 03 · 设计原则

这些原则是后续所有设计的“宪法”。任何具体决策都应能回指到其中一条。

## P0 分层与职责单一（最根本）

- **世界引擎（World Engine）** 与 **决策引擎（Decision Engine）** 严格分离。
- 世界引擎负责：时间推进、市场撮合、拓扑、消息投递、状态落盘、实验产物。
- 决策引擎负责：把“观察”变成“决策/行动”。
- 好处：换决策方式（规则→LLM→复合）不改世界；世界推进不感知 LLM 延迟。

## P1 统一 Agent 抽象，异构引擎实现

- 所有 agent 暴露同一契约（观察→决策→行动 + 可选子 agent）。
- 内部引擎可以是 Rule / LLM / RAG / Composite，甚至远端 A2A agent。
- 即：**接口统一，实现自由**。MAF 的 `Agent` / `Workflow.as_agent()` 与 MASim 的 `GeneralPlayer` 都映射到同一抽象。

## P2 控制面 / 数据面分离

- **控制面**：实验编排、配置、调度策略、配额、可观测、评估——低频、人/策略可见。
- **数据面**：actor 执行、消息、状态、LLM 调用——高频、性能关键。
- 好处：规模扩展只发生在数据面；策略调整不改数据面代码。

## P3 有状态 actor + 无状态 worker

- 状态（仓位、记忆、复合子状态）归**有状态 actor**（Ray actor，即 MASim `PlayerPersona` 的推广）。
- LLM 调用/检索等无状态重活交给**无状态 worker 池 + 队列**（借鉴 Matrix）。
- 好处：actor 序列化执行保证单 agent 内部一致性；worker 水平扩展保证吞吐。

## P4 规模可降级（scale-aware degradation）

- 同一场景在 10² / 10³ / 10⁵ 下用不同“引擎配比”运行，但**结果语义一致**。
- 降级链：LLM → RuleLLM → Rule；全量 → 抽样 → 行为聚合。
- 好处：先小规模高保真验证，再大规模低成本复现。

## P5 标准协议边界

- 内部通信走**轻量消息总线**（Info→Message→SimPacket 的扩展），不引入外部协议开销。
- 跨系统/跨语言/外部接入走**标准协议**：A2A（agent↔agent）、MCP（agent↔工具/知识）、AG-UI（人机）。
- 好处：子 agent、外部 agent、工具都能以“标准”方式插拔，契合“整齐、标准”。

## P6 幂等、可快照、可恢复

- 所有投递幂等（消息带 seq，重复不重复消费）。
- 轮级/层级快照，支持断点续跑与 time-travel。
- 好处：几十万 agent 长跑实验可工程化交付。

## P7 成本与延迟是一等公民

- 每个决策路径显式标注成本（token/秒/钱）与延迟预算。
- 系统内置 token 配额、缓存命中统计、降级触发。
- 好处：规模与成本可控，不靠“事后心疼”。

## P8 可观测与可审计

- 分层指标（agent→group→scenario），采样 trace，决策 I/O 溯源。
- 借用 MAF OpenTelemetry 与中间件插桩；关键决策保留“观察→决策→行动”完整链。
- 好处：能解释“为什么这个 agent 这么做”，能定位“哪一层先崩”。

## P9 渐进演进，不重写

- 保留 MASim 已稳定运行的内核（市场/拓扑/四阶段/消息/状态），以**适配层**方式接入 MAF 能力，而非推倒重写。
- 新能力（复合 agent、协议桥、批处理网关）以插件/可选模块加入。
- 好处：低风险落地，逐步替换。

## P10 可复现优先（对研究）

- 同 seed 同结果（规则路径严格确定；LLM 路径通过固定温度 + 缓存 + 记录模型/参数版本）。
- 决策记录包含 `model/version/prompt_hash/engine/seed`，保证可复算。
- 好处：这是“专业”与“可发表”的底线。

## 原则之间的关系

```text
P0 分层单一  ──>  P1 统一抽象 + P2 控制/数据分离
P1  ──>  P5 标准协议边界 + P6 幂等快照
P3 有状态/无状态  ──>  B5 调度解耦（见 02）
P4 规模降级  ──>  B1/B2 规模约束（见 02）
P7 成本延迟  ──>  B1 成本约束
P8 可观测  ──>  B7 治理
P9 渐进  ──>  落地策略（见 11）
P10 可复现  ──>  评估目标（见 01）
```
