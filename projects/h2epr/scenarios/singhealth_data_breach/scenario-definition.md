# SingHealth Data Breach Scenario Definition

## 1. Model overview

This dataset-conditioned Rule scenario represents H2EPR-0616 as a sparse
incident-response and public-record process. Eight reviewed organizational or
representation-gate Agents produce 17 bounded records across 20 logical
coordinates; the affected-patient cohort remains explicit context because the
Draft exposes no cohort-authored choice. The model tracks information-dependent
decisions, not malware operations, personal harm or security effectiveness.

## 2. Event boundary and process coverage

The executable process covers qualified attributed access/exfiltration records,
organizational detection, scope verification, public disclosure, leadership
direction, security review, inquiry and findings, two penalty orders, announced
remediation/oversight programs and later public attribution. It starts with a
retrospective incident record and ends after March 2019 attribution delivery.

Affected-record dates, technical exploitation, unauthorized-copy completion,
private medical data, individual notification, fine payment, implementation of
controls and causal effectiveness remain outside state. The state says which
modeled public or organizational record was admitted; it is not a cyber range or
historical database reconstruction.

## 3. Dataset basis, exposure, and temporal firewall

Only `event_spec.json`, `frozen_evidence.json` and `draft_epg.json` are admitted.
All four Draft stages were exposed. The 12 frozen records include duplicates,
truncations, retrospective accounts and unrelated material; no external
reconciliation is performed.

| Dataset issue | Executable treatment |
|---|---|
| May 2015 visit range is treated as intrusion start | access timing stays qualified; concentrated theft uses the exposed June–July account |
| Whitefly is named retrospectively | P_1 is structural; public attribution remains unrecorded until P_9 publication |
| Passive ownership, victim status, failures and penalty receipt appear as actions | roster preserves them as context/results, not selectable intents |
| E4/E5 relations reverse leadership or oversight endpoints | actor-local choices and delivered messages own authority |
| E6 relation descriptions swap penalty recipients | P_8 issues IHiS SGD 750,000 and SingHealth SGD 250,000 order records; no payment |
| E7 says reforms were implemented | current intents record announced programs and oversight only |

Generated COI findings, penalty outcomes and attribution-report values follow
their admitted actions. Their capability and field names are visible earlier;
structural identity is not evidence of report delivery or attribution truth.

This is a declared-event-vocabulary-exposed baseline: all public field names and each actor's complete capability menu are visible from the first coordinate, including event-specific future terms. Generated result values and actual receipt remain distinct from that vocabulary. No historically prefix-clean information claim is made.

World feasibility is enforced by mechanism domains and state preconditions. Only explicit handler information_requirements are mandatory receipt admission. Other message guards, activation windows and priorities are selected Rule policy assumptions, not backend-neutral historical or institutional laws.

## 6. World, institutions, relationships, and resources

The reducer owns 17 one-time fields under incident, response, IHiS, disclosure,
review, inquiry, enforcement, remediation and attribution entities. IHiS alone
observes `ihis_system_operator.scope_verification`, whose report may be qualified
or unresolved. This is an assessment record, not a forensic truth state. `unrecorded` means
that no modeled record has been accepted yet. Every transition has one authorized
handler and cannot be written by a message or foreign actor.

The world contains no patient rows, malware, host/network topology, money ledger,
fine-payment account, vulnerability state, security metric or effectiveness
outcome. Amounts, affected-record counts and Whitefly appear as qualified values
or message payloads, not conserved resources or verified truth.

## 7. Observation and communication routing

Each active actor observes sealed public prestate, current delivered messages,
its own outgoing pending lifecycle and runtime-derived received/own-action
memory. It never sees another actor's pending item, future stage label, Reference
content, private medical data or opaque generated ID as evidence.

Declared routes carry detection, scope, disclosure, leadership direction,
review/inquiry mandates, findings, recipient-specific penalty notices,
organizational program notices and public attribution. Guards require actual
delivery. The one-tick routes are explicit structural assumptions, not recovered
organizational latency.

IHiS additionally receives its own private assessment. The ministry cannot read
that field; it learns the statement through `breach_scope_summary`. This typed
message carries `assessment_status` and `scale`. A latest unresolved or withdrawn
summary does not satisfy the disclosure predicate, and a pending summary is absent
from ministry memory. Concurrent conflicting latest summaries fail the predicate.

COI findings also have a typed status: qualified findings and recommendations,
unresolved, or withdrawn. PDPC's selected Rule rows inspect that latest status;
the message kind alone does not demonstrate usable findings. Other notification
payloads remain untyped and their contents are not validated as decision evidence.

## 8. Intent, adjudication, lifecycle, and result

Seventeen event intents plus `no_op` project from eight parents. The backend
selects an intent; the environment validates actor, target, parameters and
preconditions against one sealed prestate. Only accepted intents produce world
deltas. Messages have their own admitted/delivered/rejected lifecycle.

For disclosure, shared admission also requires the latest qualifying scope
receipt and a qualified internal assessment record. Both remain necessary when
the backend bypasses its Rule guards. This is a structural information contract
selected for the pilot, not a recovered institutional disclosure rule. Other
receipt dependencies and time windows remain Rule policy selections.

Detection does not force verification. Scope verification does not itself make a
public disclosure. Direction does not implement a review; inquiry does not equal
findings; findings do not issue penalties. An order is not payment, a program
announcement is not implementation, and public attribution is not identity truth.

## 9. Configuration, variants, termination, and identity

Shared configuration owns actors, opening state, timeline, routes, observation
and termination. Rule configuration owns windows, state/message guards,
priorities, payloads and explicit `no_op`. All top-level values have provenance;
none is calibrated.

Publication requires full horizon, hash-chained trace, tick/run seals,
authoritative replay, exact final state, Generated EPG coverage and zero
unresolved transport. Descriptive expectations are reported, not release gates.
A parent or semantic change rebuilds every descendant identity; timing and route
changes remain configuration successors.

## 10. Worked cases, falsification, and limitations

- Withheld scope verification: disclosure and its dependent leadership,
  inquiry, enforcement and remediation path should remain open while qualified
  incident and detection records stay valid.
- Delayed findings: the committee may publish, yet the PDPC windows can close
  before receipt; penalties and penalty-dependent programs then remain open.
- Authority: SingHealth cannot disclose for the ministry, the COI cannot fine,
  and PDPC cannot publish the Symantec attribution.
- Result boundary: an accepted order cannot create payment; an announced
  program cannot create implemented controls or effectiveness.
- Result availability: attribution-report values before the publication action,
  or a scope receipt before delivery, falsify the package. Earlier Whitefly-related
  vocabulary remains exposed and excludes a historically prefix-clean claim.
- Scope content: unresolved assessment, a latest withdrawn summary or no delivered
  summary prevents disclosure. Delayed qualifying receipt can activate Rule within
  its window; expiry may leave a valid open endpoint. No internal forensic method,
  measured accuracy or mandatory historical timetable is inferred.

This full-Draft, logical-time construction supports dataset-conditioned
engineering and simulation-only description. It does not support historical
fit, intrusion dating, calibration, held-out performance, attacker-truth,
cybersecurity effectiveness, causality, scientific validity or generality.
