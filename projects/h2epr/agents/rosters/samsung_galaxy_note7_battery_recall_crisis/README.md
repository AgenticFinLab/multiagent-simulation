The roster accounts for all nine source IDs and 24 appearances across four stages
and nine episodes. Eight runtime representations retain supported choices; P_2
is explicit supplier/investigation context. Three cohort IDs use Population
Models, while P_8 is a disclosed incident-notification representation gate.

`roster.json` owns exact Draft accounting. `actor-map.json` owns representation
and loss decisions. Passive eligibility, supply, subject status and physical
incident occurrence do not silently become participant actions. Malformed Draft
relation/transaction endpoints confer no authority. The manifest and checksums
seal the single current release; changed representation rebuilds descendants.
