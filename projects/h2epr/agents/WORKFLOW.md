# Participant workflow

## 1. Admit the dataset boundary

Read only the event's declared `event_spec.json`, `frozen_evidence.json`, and
`draft_epg.json`. Record their hashes and the exposure mode before writing a
participant asset. Dataset records are benchmark inputs, not independently
verified historical facts.

## 2. Close the source roster

Give every Draft participant exactly one disposition:

- named Agent;
- population choice unit;
- initial context;
- world-state entity;
- scenario or institutional process;
- outside the selected window; or
- unresolved source defect.

Record aggregation, exclusion, and identifier gaps. Do not create an actor to
fill a missing identifier or preserve a historically prominent name.

## 3. Define each active decision unit

Use the Agent Definition or Population Model template. Cite dataset anchors by
file, stage, episode, participant, or stable record identifier. Define the
information and authority boundary before describing possible decisions.

## 4. Close shared interfaces

Publish observation, intent, and lifecycle registries. Each observation has
one producer and declared consumers. Each intent has an authority rule and an
environment-owned result. Pending, rejected, expired, and superseded states
remain visible.

## 5. Review as one event roster

Check name erasure, actor swaps, hidden/future information, duplicate state
ownership, always-abstain behavior, invalid intents, and aggregation loss.
Definitions are complete only when the scenario can assemble every declared
interface without inventing missing semantics.
