# SingHealth Data Breach Rule configuration

Seventeen guarded rows select bounded incident, response, disclosure, inquiry,
enforcement, program and attribution records. Inclusive windows permit waiting
for actual information; accepted rows finish once and unchanged rejection cannot
create a retry. `no_op` is the explicit fallback.

All six top-level settings have provenance. Rule cannot execute malware, pay a
fine, complete remediation, prove patient notice or establish attacker truth.
Choice changes require re-admission and rebuilt evidence.
