# Panic of 1907 Scenario Configuration

## Identity and purpose

Shared configuration `h2epr.0288.comparison.v1` selects one dataset-conditioned
institutional process; `h2epr.0288.rule.v1` owns deterministic participant choices.
It is a reproducibility baseline, not a market reconstruction, historical fit,
liquidity calibration or admitted scientific experiment.

## Exact parent boundary

The assembly pins the Source Profile, full roster/map, eleven human parents,
participant interface, Scenario and configuration releases. Maintained
declarative environment/annotation implementations own effects. The Rule
realization pins common sources; there is no event-specific runtime Python or
MASim modification.

## Rule settings and behavioral use

The Rule configuration contains 23 ordered rows with inclusive windows, explicit
state/message guards, one-action-per-actor cadence and `no_op` fallback. Accepted
rows complete once. Unchanged rejection does not trigger a retry; new delivered
information may reopen a still-available row.

Values are qualified record labels and messages. No withdrawal probability,
solvency, cash amount, interest rate, gold quantity, vote, rescue effect or policy
effect is estimated. Alternative behavior requires a semantic-parent successor.

## Variants, verification, and failure routing

Construction variants remove the Knickerbocker aid-request row or delay the
Commission recommendation route through freshly admitted successors. They may
publish with open expected fields when trace, seals, replay, graph and transport
close. They are mechanism probes, not historical counterfactuals.

Schema, provenance, source, release, actor, intent, route or hash mismatch fails
admission. Runtime rejection changes no state and preserves its disposition.
Unresolved transport or replay/graph/rematerialization mismatch blocks release.
