# Lebanese Civil War Scenario Configuration

## Identity and purpose

Shared configuration `h2epr.0892.comparison.v1` selects one dataset-conditioned
public-record process; `h2epr.0892.rule.v1` owns deterministic participant choices.
It is a reproducibility baseline, not a conflict forecast, combat, responsibility,
constitutional or peace-effectiveness model.

## Exact parent boundary

The assembly pins the Source Profile, complete roster/map, eight human parents,
interfaces, Scenario and configuration releases. Common declarative environment
and annotation implementations own effects. There is no event-specific runtime
Python, model/network access or MASim modification.

## Rule settings and behavioral use

The Rule configuration contains 33 ordered rows with inclusive windows, state
or delivered-message guards, one action per actor/coordinate and `no_op`
fallback. Accepted rows finish once; unchanged rejection does not reopen them.

All values are qualified public or organizational records. No force, casualty,
territory, weapon, aid, military utility, bargaining utility, agreement
implementation or peace outcome is estimated.

## Variants, verification, and failure routing

Construction variants omit Amal's mediation notice or delay the PLO-to-Hezbollah
camp-defence route. Open expected fields can publish only when trace, seals,
replay, graph and transport close. These are mechanism probes, not historical
or intervention counterfactuals.

Schema, provenance, source, actor, intent, route or hash mismatch fails
admission. Runtime rejection changes no state. Unresolved transport or
replay/graph/rematerialization mismatch blocks release.
