# Baoneng–Vanke Takeover Battle Scenario Configuration

## Identity and purpose

Shared configuration `h2epr.1031.comparison.v1` selects one full-Draft,
dataset-conditioned process baseline. It owns backend-neutral opening state,
time, actor and communication assumptions; `h2epr.1031.rule.v1` owns
deterministic participant choices. These are construction/reproducibility checks,
not an admitted multi-backend scientific experiment or a tuned takeover policy.

## Exact inputs

The assembly pins the Source Profile and roster, participant-interface, Scenario
and configuration release manifests. Those manifests include every human parent,
interface, mechanism, coverage record and admission receipt by path/hash. The
environment is `h2epr.environment.declarative.v4`; annotations use
`h2epr.annotations.declarative.v3`. The realization pins the common Rule source
inventory; the compiler independently reconstructs all admission receipts.

Waiting is meaningful when a specific statement or prior own/counterparty record
is absent. Rejected rows retry only after new visible information, not merely a
tick change or their own rejection; accepted rows finish once. The operating
report has a one-coordinate window because it represents the exposed dated H1
statement at the early-stage boundary, not a recurring financial-monitoring Rule.
One action per actor per tick and ascending priority may defer later own rows.

The nominee-delivery construction probe changes configuration through fresh
admission and compilation. It must preserve the independent earlier acquisition
disclosure and allow a valid open nomination endpoint; it must never patch a
sealed package or demand a fabricated election result to make release pass.

## Validation and promotion

Schema checks, exact parent lineage, complete actor/intent/field/route closure,
full provenance, typed shared/Rule admission and source inventories precede
compilation. Configuration receipts are independently rederived, not accepted
because their producer sealed them. A/B materialization, opaque-ID perturbation,
trace/seals/replay, graph reconstruction and independent publication follow.
Changing a guard/route requires a new configuration identity and all dependent
evidence. Changing a represented owner or record meaning first revises its
semantic parent. Outcome expectations cannot waive an integrity failure.
