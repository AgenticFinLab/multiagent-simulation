# End-to-end benchmark event guide

## Phase contract

Use one event workspace and advance only when the preceding parent is accepted:

| Phase | Product | Admission evidence |
|---|---|---|
| 0 | Git/exposure preflight | exact branch/tree and authorized endpoint |
| 1 | Source Profile | three direct paths, hashes, schema, claim boundary |
| 2 | build brief and roster | every Draft participant dispositioned |
| 3 | semantic parents | reviewed Agent/Population products |
| 4 | interface releases | actor and registry closure, parent hashes |
| 5 | Scenario release | world authority and executable mechanism closure |
| 6 | shared/backend configuration | exhaustive provenance and admission receipts |
| 7 | backend realization | complete actor/intent/failure coverage |
| 8 | event package | compiler-derived core/catalog/binding identities |
| 9 | raw materialization | sealed custody, replay, graph, transport closure |
| 10 | compact release and reading | independent verification and complete-output account |
| 11 | current promotion | registry row and repository-wide discovery checks |

Cross-event conformance is available only when at least two independent current
events exist. It is evidence about the shared engineering contract, not an
event's prerequisite for an otherwise valid individual release.

## Read and command sequence

Read the repository guide, benchmark protocol, workflow, publication standard,
event-authoring guide, run/release guide, schemas, templates, and relevant
specialized Skills. Use `python -m h2epr.cli --help` for the maintained command
surface. Validate the registry, compile to an absent output root, validate the
attached package, materialize fresh roots, test identity invariance, publish
from sealed custody, and validate the registry again after promotion.

Commands never authorize the next phase. Record a closeout disposition and
next legal action at each maintained boundary.

## Stop and resume record

On stop, record current phase/product hashes, accepted parents, dirty paths,
exposure, validations completed/failed, raw custody locations, unresolved
findings by owner, prohibited next actions, and the one next legal action. On
resume, recheck Git/input identities before trusting the record.

## Feedback classification

| Finding scope | Destination |
|---|---|
| one event vocabulary or unsupported source fact | event asset/limitation |
| repeated author decision or missing product field | template or Skill |
| invalid machine shape or cross-file invariant | schema/validator |
| reusable execution behavior | H2EPR common code plus synthetic regression |
| MASim kernel defect | separate MASim-owned work; do not patch through H2EPR |

Reduce a proposed shared change to a synthetic case first. Re-run that case and
the complete framework suite before applying the correction to a real event.

## Completion evidence and final acceptance

Acceptance requires one authority per semantic fact, exact parent lineage,
complete roster and backend coverage, no event vocabulary in common Python,
exhaustive configuration provenance, implementation source hashes, typed
failure routing, fresh custody, complete trace/seals/replay/graph, zero terminal
transport, repeatability or complete model provenance, compact release,
complete-output reading, current registry discovery, resolved links/checksums,
clean Git state, exposure declaration, bounded claims, and a reproducible
command record.

Report every identity and count named in the Skill entrypoint. State separately
what the event establishes, what remains planned, what failed, and what the
next authorized scope would be.
