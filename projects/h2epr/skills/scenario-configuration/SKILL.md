# Scenario configuration

Read [references/guide.md](references/guide.md) for the setting ownership
matrix, provenance classification, exhaustive pointer coverage, worked
admission failures, and promotion evidence.

## Procedure

1. Pin exact semantic parents, schemas, environment/annotation IDs, and
   implementation sources.
2. For shared comparison configuration, select ordered logical coordinates,
   Draft stage/episode anchors, active actor IDs, typed initial state, explicit
   routes, observation contract, termination, and declared exogenous values.
3. For Rule configuration, publish coordinate/actor/priority rows, guards, one
   typed action, optional messages, and a declared `no_op` default. Other
   backend configurations contain only their decision-production settings.
4. Label every top-level selected setting dataset-derived, structural,
   synthetic, sensitivity, model, or run-local. Publish a self-hashed
   provenance coverage asset whose covered pointers and typed exemptions form
   an exact, non-overlapping partition of `/settings/*`.
5. Reject undeclared defaults, uncovered settings, unreviewed exemptions,
   unknown fields, unsafe paths, parent drift,
   actor mismatch, out-of-domain values, and backend settings in the shared
   profile.
6. Derive the admission receipt independently from the semantic parents and
   configuration. Reject a merely self-hashed producer assertion.
7. Publish configuration design, JSON, provenance coverage, admission receipt,
   manifest, and checksums.

Admission proves identity and static closure only. It does not prove backend
behavior, runtime readiness, repeatability, or scientific validity.
