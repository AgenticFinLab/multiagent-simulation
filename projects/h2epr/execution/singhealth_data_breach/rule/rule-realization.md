# SingHealth Data Breach Rule realization review

## Decision ownership

The realization maps eight exact actor IDs and 17 event intents plus `no_op` to
the maintained declarative Rule decision engine. Rule owns row selection only.
The backend-neutral package owns participant/scenario semantics; the environment
owns admission/effects, MASim owns transport/trace order, and publication owns
independent evidence derivation.

## Behavior and temporal review

Rows use inclusive windows, public prestate, IHiS-private assessment state and
actual delivered-message memory. The qualified assessment is a selected Rule
report; an unresolved assessment is also in the admitted action domain. Disclosure
requires the latest typed qualifying summary, while shared admission independently
checks receipt and the private assessment. Other windows and message guards remain
policy selections. Static reasons are labeled rationale and linked to exact
observations; they are not generated forensic findings.
The P_1 representation sends no early attribution. Detection, scope, disclosure,
direction, inquiry, findings, penalties and programs remain separable. One actor
may emit at most one action per coordinate; `no_op` is explicit waiting.

## Failure and reproducibility review

Missing information produces waiting/open endpoints rather than source-stage
autocompletion. Foreign intents or targets are typed rejections with no delta.
Implementation sources are exact-hashed; model/network fallback is absent.
Fresh A/B, generated-ID perturbation, replay, graph, seals and independent
rematerialization remain run-release obligations.

## Boundary

Acceptance demonstrates deterministic attachment to one admitted semantic
package. It does not validate incident timing, actor truth, historical fit,
security effectiveness, policy effects, causality or scientific generality.
