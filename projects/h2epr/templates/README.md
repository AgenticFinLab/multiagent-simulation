# Templates

Templates provide one maintained authoring surface for each product. They
state responsibility and review questions; JSON schemas remain authoritative
for machine shape.

| Template | Use |
|---|---|
| [event-package](event-package/) | Compile the current semantic core and attach registered backends |
| [source-profile](source-profile/) | Admit exactly the declared benchmark files |
| [roster-release](roster-release/) | Publish the source roster, actor map, and interfaces |
| [backend-binding](backend-binding/) | Attach one implemented decision backend |
| [run-release](run-release/) | Publish compact run and reproducibility evidence |
| [event-build-brief-template.md](event-build-brief-template.md) | Start a dataset-only event build |
| [phase-closeout-checklist.md](phase-closeout-checklist.md) | Close a maintained construction phase |
| [simulation-reading.md](simulation-reading.md) | Read one sealed generated process |
| [backend-comparison.md](backend-comparison.md) | Compare runs sharing package/runtime identity |
| [cross-event-analysis.md](cross-event-analysis.md) | Compare event-neutral contract evidence across domains |
| [experiment-plan.md](experiment-plan.md) | Review a run matrix before execution |
| [experiment-closeout.md](experiment-closeout.md) | Account for every planned row and attempt |

Layer-specific templates remain beside `agents`, `populations`, `scenarios`,
`configs`, `backends`, and `execution`, where the owning guide links them.
