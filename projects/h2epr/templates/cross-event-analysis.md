# Cross-event analysis template

Compare events only after each case passes its own package, runtime, replay,
graph, and release gates. Record the exact case count and the contract identity
shared by those cases.

## Compared cases

List event, backend, package, binding, runtime and MASim source inventories,
run, trace, final state, and Generated EPG identity. State construction
exposure and seed set for every case.

## Contract conformance

Check distinct event identities, package schema family, backend-catalog
agreement, selected-backend availability, output roles, source inventories,
replay, trace coverage, transport closure, and claim exclusions. A failed case
remains in the failure ledger and does not enter aggregate interpretation.

## Process variation

Compare structural quantities and mechanisms only where their definitions are
event-neutral. Keep event-local vocabulary, state fields, and lifecycle
interpretation in the event reading. Explain missing or non-comparable values;
do not coerce them into one domain-specific metric.

## Interpretation and limits

Separate direct receipt facts from interpretation. More passing domains widen
engineering evidence for the contract, but do not establish historical fit,
calibration, held-out performance, causal validity, scientific validity, or
universal generality.
