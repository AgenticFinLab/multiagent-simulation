# AnchoringEffect LLM — Implementation Explanation

## §1 Overview

| Item                                   | Description                                                                                                                                                                                                    |
|----------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Variant**                            | LLM (pure language model reasoning)                                                                                                                                                                            |
| **Implements**                         | `../simulation-bases.md`                                                                                                                                                                                       |
| **Decision Logic**                     | LLM prompts (persona only) — no explicit formulas in prompts; LLM discovers market dynamics from per-round user prompt data                                                                                    |
| **Key Difference from Other Variants** | Market is rule-based (identical to Rule variant); investor decisions are generated by LLM from personality-only system prompts — no quantitative rules embedded                                                |
| **Primary Research Contribution**      | Test whether LLM agents, guided only by behavioral personality and market data, can reproduce anchoring-like price stickiness without explicit anchoring formulas                                              |
| **Core construction rule**             | System prompts define **personality only** — must NOT name the phenomenon, mention the price formula, or hint at what market event is occurring; LLM must discover dynamics from user prompt market data alone |

## §4 Variant-Specific Features

*(Reference: simulation-bases.md §9 — LLM variant entry)*

**Persona-only system prompts**: System prompts define behavioral personality, psychological biases, and decision tendencies. They do NOT contain:
- The word "anchoring" (target leakage)
- Any explicit formula (e.g., `perceived_target = anchor + ...`)
- Any mention of "cognitive bias" or "heuristic"
- Any reference to the price formula or market mechanism

**Output format**: Both system and user prompts specify the canonical output format:
```
First output your reasoning in <analysis>...</analysis> tags,
then output your decision in <decision>...</decision> tags.
The decision must be valid JSON:
{"action": "buy"|"sell"|"hold", "bid_price": float, "quantity": float, "reasoning": string}
IMPORTANT: bid_price and quantity MUST be numeric values (e.g., 10.5), NOT expressions or formulas.
```

**LLM client initialization**: `LangChainAPIInference` initialized with `lm_name` and `generation_config` from players.yml `extras.llm`. Client is stored in `custom_state` to survive Ray checkpoint.

**Retry logic**: 3 retry attempts for LLM parsing failures; fall-through to `hold` with quantity = 0 after exhausting retries.

**Portfolio management**: LLM decisions are applied with cash/position constraints in `decide()` (same logic as Rule variant).

## §6 Configuration Reference

Key Configuration Parameters (`configs/AnchoringEffect/LLM/players.yml`):

| Parameter           | Config Path                    | Value                    | Design Justification                                          |
|---------------------|--------------------------------|--------------------------|---------------------------------------------------------------|
| `sys_message`       | `extras.llm.sys_message`       | module:CONSTANT path     | Points to persona-only system prompt; no formula content      |
| `user_message`      | `extras.llm.user_message`      | module:CONSTANT path     | Points to `LLM_USER_TEMPLATE` with market state variables     |
| `lm_name`           | `extras.llm.lm_name`           | `ep-xxx` (Doubao model)  | ByteDance ARK API endpoint; loaded from config, not hardcoded |
| `generation_config` | `extras.llm.generation_config` | `{max_tokens: 512, ...}` | Controls LLM output length and sampling                       |

All market parameters identical to Rule variant. See `simulation-bases.md §6` for source citations.

## §8 Expected Behavior Patterns

| Phase           | Rounds | Expected LLM Agent Behavior                                                                   | Expected Price Dynamics                                                     |
|-----------------|--------|-----------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| Early Anchoring | 1–10   | LLMAnchoredTrader "feels" initial price is fair; resists selling despite deviation            | Price stays near initial level; slower correction than Rule                 |
| Persistent Bias | 10–60  | LLMHistoricalAnchor references "historical average" in reasoning traces                       | Deviation persists 3–10%; higher variance than Rule                         |
| LLM Drift       | 30–70  | Some LLM agents may "update" their view more than Rule agents — LLM can reason beyond formula | Deviation decay may be faster OR slower than Rule depending on LLM sampling |
| Correction      | 60–100 | LLMRationalUpdater consistently argues for fundamental value in reasoning                     | Convergence toward fundamental; LLM variant noisier than Rule               |
