# ReversalEffect Analysis Bases

## §1 Analysis Objectives

The analysis verifies whether the simulation produces an overreaction path,
whether contrarian and value demand appear near extremes, and whether price
partially corrects toward fundamental value. It also checks the structural
requirements for a full 200-round experiment: complete market series, finite
prices, non-trivial order flow, and auditable LLM/RAG fields where applicable.

## §2 Metrics

### §2.1 Overshoot Magnitude

```python
def compute_overshoot_magnitude(prices: list[float], fundamental: float) -> float
```

Measures the maximum absolute percentage deviation from fundamental value.

### §2.2 Reversal Return

```python
def compute_reversal_return(prices: list[float], onset: int, extreme: int) -> float
```

Measures the correction from the price extreme to the later reversal phase.

### §2.3 Contrarian Order Share

```python
def compute_contrarian_order_share(orders: list[dict]) -> float
```

Measures the fraction of total signed volume generated by contrarian or value
agents against the prior move.

### §2.4 Momentum Delay

```python
def compute_momentum_delay(prices: list[float], orders: list[dict]) -> int
```

Counts how many rounds continuation pressure persists after the first large
deviation.

### §2.5 Liquidity Depth

```python
def compute_liquidity_depth(orders: list[dict], base_liquidity: float) -> float
```

Measures effective depth in RuleLLM and Rag variants using orders marked with
`provides_liquidity`.

### §2.6 Agent Attribution

```python
def compute_agent_attribution(orders: list[dict]) -> dict[str, float]
```

Attributes continuation and reversal pressure to strategy classes.

### §2.7 API Quality

```python
def compute_api_quality(events: list[dict]) -> dict[str, float]
```

Reports parse-failure, retry, explicit fallback, and RAG retrieval coverage
rates for API variants.

## §3 Analysis Dimensions

The primary dimensions are price deviation, reversal timing, order-flow
composition, role attribution, liquidity depth, portfolio exposure, and API
quality. The same structural analysis outputs are required for all variants so
the deterministic baseline and API variants can be compared consistently.

## §4 Phase Analysis

The phase framework has five stages: initialization, overreaction buildup,
continuation or delayed reversal, contrarian/value correction, and terminal
stabilization. A valid run does not need a perfectly symmetric reversal, but it
must expose enough price and order-flow variation for these phases to be
identified.

## §5 Cross-Variant Comparison

Rule establishes the deterministic benchmark. LLM tests whether persona-driven
orders retain the reversal mechanism under stochastic text generation. RuleLLM
tests whether explicit rules stabilize API behavior under liquidity-aware
pricing. Rag tests whether retrieved domain knowledge changes timing, order
size, or liquidity provision while preserving the same schema.

## §6 Expected Results And Validation Criteria

A valid full experiment records 200 market rounds, finite prices, nonzero
volume, bounded deviation, and at least one phase of correction after an
extreme. API variants should have a low parse-failure rate and no deterministic
schema failures. RAG variants should record `rag_context` and `rag_stats.json`
so retrieval coverage can be reviewed.

## §7 Visualization Plan

Required analysis outputs are `summary.json`, `00_investor_bids.png`,
`01_reversaleffect_dynamics.png`, `02_reversaleffect_analysis.png`, and
`03_summary.png`. Rag additionally writes `rag_stats.json`. Scenario-specific
